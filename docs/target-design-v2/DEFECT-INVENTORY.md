# 2. step time 仿真链（32 条）

## 2.1 问题的形状 —— 一处结构性反直觉

时间链**有**外部裁判（真机 op 级 time 记录），这在缺陷分布上体现成三点：

1. 缺陷集中在**"这个裁判有多强"**（能力边界 7 + oracle 强度 9 = 16 条，占一半），而不是"两处规定不能同时为真"。
2. 已修率 14/32 明显高于显存链——有 oracle 的地方"对不对"有确定答案、能收敛。
3. **但外部裁判换来的是门的强度，不是产物的价值。** 显存侧用整个第 10 章把"我们不知道"做成
   `Q3[Bool]` + 判定阻碍分解；时间侧的头号输出 `step time` 是 `Sample`，**在类型上不能与任何东西比较**，
   连一个 `undetermined` 都没有。**有裁判的那条链，产物形态反而是全案最弱的。**

# 4. 本次归类才看见的七件事

1. **102 : 32 不是"显存问题多"，是"显存被看得多"。** 时间链有 10 个构件零攻击，其中包含
   `step time` 的唯一生产者。时间链的 32 是**下界**，不是计数。

2. **零攻击的方法论成因**：每一轮反驳都按零逃逸六判据构造，而六判据的射程是"用户可以补充信息的通道"。
   **不接受用户输入的构件在这套方法论下没有攻击面。** 这是红队制度本身的盲区，不是疏忽。

3. **有外部裁判的那条链，产物形态反而最弱。** 裁判买到的是门的强度，不是产物的价值。

4. **地基是修得最少的一层**（未修 28 / 阻断实施 17），而两侧的缺陷都从这里长出来。

5. **十组裁定里七组的前提已不成立**，而裁定表没有"依赖哪一行正文"这一列。
   裁定 #7 甚至写了"免得后来者当作缺陷改掉"——**那句话保住了文字，没保住前提**。

6. **复述发散是 13 项不是 8 项，`S_∞` 的口径是 11 处不是 4 处**；核对器覆盖 2/13，
   而**唯二没发散的恰好就是唯二被覆盖的**。这是"上核对器就有效"最直接的证据。

7. **`exact` 的 User 域逃逸仍开着**：`registry_domain = Native` 这条准入只落在代数一处，
   加载期校验与复活检测两处都只查三条，而 §6.4 还在称 `block_code` "不可伪造"——
   与代数那处正面矛盾。这是一条零成本、四处指标同时变好的逃逸。

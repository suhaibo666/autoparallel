Chapter 0导读与硬前提

这份文档回答一个问题：如果从原理出发重新设计这个仿真器的模型表示，其目标形态应当如何。 它不是现有代码的改造清单。每一层说明四件事：是什么、为什么这样切、 主要数据结构、数据流与逻辑流程；此外每引入一个新构件，都要过一遍零逃逸六判据。

0.1 三条硬前提

本方案的大部分非显然之处都从这三条流出。它们不是设计选择，是外部裁定的约束， 设计只能在其中求解。

前提内容它删掉了什么
P-oracle 真机对照数据仅限 op 级 duration 记录（含 op 序列本身——逐 op 计时蕴含"哪些 op 跑了、跑了几次、什么次序"） allocator snapshot、活跃集合、保活集合差分、各 rank 分片形状 dump、显存事件序
P-peak 端到端峰值标量同样排除（峰值是显存量，不是 time 记录） 显存链的最后一根外部柱子
P-noexc 不接受任何人工例外条款。"评审"、"责任人"、"到期日"、"豁免"都是流程而不是机制 全部 waiver / accepted delta / 告警式放行
P-oracle + P-peak 的直接后果，必须先说

显存链没有任何外部裁判。峰值与 OOM 判定这个头号输出，其正确性只能由内部一致性、 与源码文本的对照、以及时间侧 oracle 的间接约束提供。

因此本文对显存侧的一切检查一律称自洽性检查，禁止使用"验证 / 校验 / 正确性判据" 这三个词——它们会让读者以为存在一个说"算对了"的东西。报表首页强制打印这一事实（见 第 10 章）。

唯一允许的外部信号是用户自发报告的 OOM 布尔事实，且它只能做反证：进缺陷台账， 不得作为标定输入，不得成为 CI 门。理由——用户的偶发观测不可复现、无指纹， 拿它去标定就是用链的输入裁判链自己。

特别地：框架 OOM 报错文本里的数字（tried to allocate X bytes、 reserved Y、free Z）同样排除。它是本方案最便宜的一条旁路—— 不需要 profiler、不需要改框架、用户随手一贴就有，而它恰好给出显存链最缺的那个数。 可采信的只有"这次跑 OOM 了"这一个比特；报错文本里的任何数值都不得进入链的任何位置， 这一条必须在实现里以指纹表显式登记（G-X4）。

0.2 零逃逸六判据

本方案的每一个"用户可以补充信息"的通道，都必须过这六条。它们是全篇的验收器：

#判据它挡住的失效模式
1可证伪性：存在一个观测能与之矛盾不可证伪的声明等于装饰
2可达阻断性：违反时有一条真的到达 BLK-* 的路径标签式"告警"——它不是类型
3非普适性：不能给所有量都打上它万能通道等于没有通道
4被计数且被设阈：有首页数字，有触发后果可见但无后果 = 无成本
5代价单调性（硬）：用了它，答案形状必须变差。强形式：同一份配置内不存在一种填法使答案变好本方案最主要的失效模式：补救使指标变好 ⇒ 人被激励去用它
6设置权归属已放弃——真实场景里使用者就是算子语义作者，"只有作者能设"不是辩护
为什么判据 5 是硬要求，而其余五条是必要条件

前四条保证"逃逸可见"，第六条保证"逃逸难做"。但可见且难做的东西，只要做了有收益， 长期一定会被做——尤其当收益是"报表更好看"而成本是"读者要多看一行"。

判据 5 换一个方向：让逃逸在收益侧就不成立。用户来这里要的是一句"装得下，余量 X GiB"， 那么任何一条补救都必须让这句话更难拿到。这是全篇唯一不依赖人的自觉的判据。

Chapter 1总体架构与分层

1.1 主线

以框架源码在策略单位元 π₀ 处的偏特化残差为模型结构的唯一入口，得到 policy-free 的 CoreIR；以纯配置描述的原子 Op 语义补齐源码证明不了的算子契约； 其后每一层策略都由一个只增不改的改写 pass 注入，pass 必须能重建源码在真实策略下本来会写出的东西 （PGRO）；最后由显存与时间两个只读后端消费同一份 SchedIR。

1.2 分层判据：G-L1

一个自然的判据是"每层只增加一类信息"。它不可证伪——"一类信息"没有机器定义， 永远可以把两类说成一类，也永远可以把一类拆成两类。新判据把层数从审美问题变成记账问题：

G-L1 · 分层判据

每一层的输出必须至少绑定一条独有不变量——该不变量在上一层的类型里不可陈述（对象还不存在）， 在下一层的类型里不再可陈述（对象已被改写）。且每条不变量必须有一个已实现的检查器。

停止条件：若某层的独有不变量集合为空 ⇒ 该层必须与相邻层合并。CI 断言"每层的检查器清单非空"。

为什么是这条，而不是"按变化频率分层"或"按数据依赖分层"

按变化频率——理由通常是"并行策略是 what-if 的主要变量"。但本方案的产品形态是 "配好配置直接出结果"，不存在拖滑块的消费者；而"变得勤"本身也没有机器定义。 既无消费者又不可证伪。

按数据依赖只能推出偏序，推不出层数——任意细分都满足数据依赖。

只有"不变量的断言点"同时给出层数的上界（不变量的条数）与下界（每条不变量必须有位置）。 它的代价是：加一层就必须交出一条不变量 + 一个检查器，交不出就不许加。

相邻对顺序理由
G0.5 在 G1 之前 反向模板是逐 op 查表的（granularity(bwd(op)) = template(op)）⇒ op 集合必须在反向生成前定稿。 若把 quantize / 融合 kernel 的替换排在反向之后，就必须为这些新节点另行生成对偶——那正是"第二套反向机制"。 放在前面，它们的反向由同一个 Pass_train_step 按各自注册的模板生成，代价为零

G2 在 G3 之前重算副本是已切分、已插通信子图的结构复制
G2.5 在 G2 之后融合对象是 shard 产出的通信节点
G3 在 G4 之前实例化必须在图定稿后
G0.5 内部三 pass 的固定序，以及它为什么对外原子化

G0.5 内部固定为 impl_select → fusion_logical → precision_fwd：前向精度要插 quantize 节点， 而插在哪里依赖实现族的选择（融合 attention 的量化点与非融合的不同）。

三者合起来对外是一个原子步——只暴露 G0.5 的 digest，不暴露中间态。"原子"仅指两件事：(i) 对外的 digest 粒度；(ii) 层序表中不存在可重排的自由度。它不意味着内部三个 pass 不可单独调用——PGRO 的形式参数 Pass_X 与 G-B1a 的 S_P 构造都必须能单独取到其中某一个；严读成"只能整体调用"会使 attention_backend、*_fusion、精度类字段全部落 BLK-UNRECONSTRUCTIBLE。这是为了不把内部序 误当成可重排的自由度：若把中间态暴露出去，层序表就会多出三个相邻对，而它们之间的顺序 并不由物理理由决定，而是由"谁先谁后都能跑通、但结果不同"这种最坏的性质决定。

1.4 全局不变量

不变量
  1. 单向：改写 pass 只读上游，任何层都不回写上游。
  2. policy-free 核：∀f ∈ G0: policy(·) ∉ f.roots；策略只能由 pass 重新引入。
  3. 改写纪律：一切改写只能以"新增带合成标记的节点与存储"实施， 不得以"就地修改源节点的形状/属性/存储"实施（由 G-C1 机器执行）。
  4. 唯一绑定：一个原子源码调用在一次编译中只能解析到一条 Op 语义。
  5. 无 opaque：可执行 IR 中不存在未知算子或不透明节点。
  6. 缺失 ≠ 空：字段缺失（未描述）与显式空值（描述为无）严格区分。
  7. 全或无：预检不过就不产生任何可供后端执行的部分计划。
  8. 身份不靠名字：逻辑值、逻辑存储、放置、物理实例是四个独立 ID（第 5 章）。
  9. Prov 只升不降：代数里不存在使 provenance 任一分量下降的算子（第 2 章 P8）。
  10. 无标量出口：峰值只有区间形态；step time 只有 Sample 形态 （它由 makespan 合成，而 makespan 是 Sample[Float]，且不存在 Sample→Q 的转换算子 ⇒ step time 在类型上就不可能是区间）。两者都没有标量形态。

Chapter 2横切契约：provenance 代数

2.1 一维 provenance 为什么不成立

最自然的写法是一个三值枚举，并把 derived 定义为"由建模范围内的事实推出（源码 + 算子定义）"。 "算子定义"四个字就是漏洞本体——注册域就是"算子定义"，于是：

  • 把 ColumnParallelLinear 判成逻辑 Linear 并注册为原子 ⇒ 它的 shape/storage 面来自注册域 ⇒ 按定义是 derived ⇒ 区间塌成点 ⇒ 阻断消失 ⇒ CoreIR 更小 ⇒ 报告 100% derived。每一个指标都变好。
  • 把某个策略字段改判为"模型变量" ⇒ 污点判据不再触发 ⇒ 阻断消失，该量仍是精确值。同样每一个指标都变好。

两条路径的共同结构是：人的一次判断被系统当成了一条事实，而事实是零代价的。 所以代数必须做且只需做一件事——

让经人工判断获得的语义在代数里是一个与源码事实类型不同的东西， 且这个类型差别是机器计算的、不可声明的，并强制向下游传播到每一个字节。

2.2 两条正交轴

一维枚举把两件正交的事压成了一条。拆开是全章的地基：

轴回答什么用途
roots输入的叶子事实来自哪里归因："如果这条根错了，多少字节会变"
certainty即使输入全对，我们施加的那个函数是不是真的那个函数形状："答案该是点还是区间"
一处根因，两处症状，一次修复

旧代数把 certainty 定义成 roots 的函数（"roots 必含标定根才算 modeled"）。这一条同时造成：

症状一：roofline 时长 = flops / peak_flops，两个输入都精确、根里无标定 ⇒ 判成 derived。 allocator 的池划分/对齐/split 阈值同理。代数里没有"机制确定性、但我们的公式可能不准"这个位置。

症状二：通信节点的字节 = prod(shape)*sizeof(dtype)，形状全来自源码，根里没有也不该有标定根 ⇒ 旧定义下只能算 derived ⇒ "通信字节的 modeled 占比必须 > 0"这道嗅探门恒不可满足。

floor_div 是我们自己的定义，不存在"可能不是那个函数"；allocator_align 是对别人机制的复刻， 输入再准也可能错。所以 certainty 是算子的属性，不是它参数根的函数。

Root :=                                                    # **闭集，八种**
  source(anchor)                    # 模型源码 AST 上、经 PE 求值得到的事实（内容寻址）

           op_identity_mapping, psi_projection, canon_ruleset }        # 闭集

      （否则报表分不清「我们放弃读源码」与「根本没有源码可读」）

policy(q) :⟺ ∃ p ∈ roots(q) : p = configured(f) ∧ class(f) ∈ { Π_extent, Π_impl }
#   于是 policy-free 断言「∀f ∈ G0: ¬policy(f)」是一次对 roots 的可判定查询，
#   Root 保持八值闭集；且改分类表使谓词失效 ⇒ 自动落进 §3.3(a) 要罚的那条路径

Evidence  := { grade ∈ {calibrated < vendor_documented < reconstructed}, ref, sweep }
Direction := exact | upper | lower
Q3[Bool]  := true | false | undetermined                   # **无到 Bool 的转换算子**
Sample[T] := 观测样本的极值集合                             # **不是界**；无区间算术、无比较、不进 OOM 链

四处非显然的取舍，各一句理由

取舍理由
"使用者给的量"拆成 configured + transcribed 它混装了"定义问题的量"（tp=8，不可证伪且应当精确）与"我们对环境的转录"（HBM 容量、池划分，高度可证伪且我们可能抄错或过期）。两者的证伪手段完全不同，不能共用一个根
新增 declared_semantics 与 abstraction 把"人的判断"从"算子定义"这个合法来源里拆出来（§2.1）。分成两种而非一种，因为二者证伪手段不同：无 AST 的声明可以有标定点；对可读源码的抽象不可能有比源码更强的证据
Evidence 与 Direction 从 assumed 专属升为全类型字段 modeled 也需要证据等级；direction 需要在 assumed 上强制单侧
删除 direction: nominal 它使区间塌成点——一个"标称值"在区间算术里与精确值不可区分。 certainty = assumed ⇒ direction ∈ {upper, lower}，必然单侧开口
三个惯用名的地位

derived / modeled / assumed 不是类型，而是 certainty 的命名投影： name(q) = derived iff certainty(q) = exact，其余同理。投影是全函数、无重叠。 roots 是正交的第二个轴，不参与命名。

modeled 的新定义：该量的产生过程中至少经过一个 self_certainty = modeled 的算子， 即我们复刻了一个不属于我们的机制。"根里必须有标定"从定义降级为证据强度（evidence.grade）。

2.4 readability：一个机器计算、用户不可设的三值分类

每一次"注册为原子"都发生在一个具体的阻断点上，而阻断发生时 PE 已经知道它当时能读到多少。 把这件已知的事升格为注册表的必填字段：

RegistryEntry.origin : {
  block_code   : BLK-*                       # 触发注册的阻断码
  site         : H(qualname, framework_ver)  # 内容寻址锚点，不含行号
  readability  : NONE | PARTIAL | FULL       # ← PE 在阻断时刻计算并写入，**用户不可填**
}

readability(target) :=
  FULL     PySub 可解析 target 的全部可达体，PE 已求出残差
  PARTIAL  可解析入口，但体内有一个或多个 BLK-* 站点（站点集随之记录）
  NONE     target 无 AST（C 扩展、内置、二进制 kernel）
为什么用"AST 在不在"，而不是别的判据

需要一个"这次抽象是不是掩盖了可读源码"的判据，而唯一不可能被声明伪造的候选是"AST 在不在" ——它是框架源码的客观属性，不是任何人的意见。

NONE → FULL 不可能（没法给 C 扩展凭空造 AST）；FULL → NONE 需要改框架源码使 PE 读不懂， 而这会改变框架源码的 digest，digest 进报告首页。代价是"我为了让报告好看去改了框架源码"这件事被打印出来。

分派规则由 readability 机器决定，不由人选。 适用范围必须先钉死：本表只作用于 origin.block_code ≠ null 的条目—— 即由一次阻断产生的注册项。工具出厂自带的 native 语义（block_code = null） 不背 abstraction / declared_semantics 根——它们不是对任何东西的抽象。

它们的证伪手段不同。NONE 的声明可以有标定点（融合 kernel 的 workspace 能被实测）； FULL 的抽象不可能有比源码更强的证据——我们手上就有源码却选择不看， 所以证据等级只能是 reconstructed，这一格由 schema 钉死，不是自觉。

阶梯的代价方向需要两处校正，否则它是反的

朴素实现下这个阶梯的代价方向是反的，FULL 被严格支配：FULL 要吃抽象残差区间、 进两道 Θ 门；PARTIAL 因"体内有阻断站点"而算不出完整残差；NONE 若声明为 calibrated， 则对两道 Θ 门同时隐身。于是最省事的做法是把可读的东西弄成不可读的。两处校正，都是定义级的：

  1. θ_abs 的分子是两个根的并：abstraction_covered_bytes + declared_semantics_covered_bytes。 只算前者，等于给"声明无 AST 对象的语义"开免费通道。
  2. PARTIAL 不得因残差算不全而退回点值：可求值部分照算残差，未求值站点各自成为 独立的 abstraction 条目并按 §2.5 的 P5 兜底取单侧。缺少信息不能换来更窄的区间—— 这是 P5 兜底条款存在的全部理由。

P5 兜底条款：为什么不能"保持点值"

一个看似克制的兜底是：evidence.grade ∈ {vendor_documented, reconstructed} 时 own_residual 无机器来源 ⇒ 不伪造一个数 ⇒ 该量的 interval 保持点值。 拒绝伪造是对的，保持点值是错的。

后果：不可验证的那一部分字节（结构上正是最该被怀疑的那部分：allocator 行为、融合 workspace、 通信复刻、分桶规则）对区间宽度的贡献恰好为零。于是"峰值只有区间形态"这条不变量被架空—— 输出是一个伪装成区间的点估计，而且它最容易错的方向（低估）正是用户最想采信的那个方向 （"装得下"）。

所以兜底不是"保持点值"，而是"取单侧"。含义是——我们不知道它的宽度， 所以我们不声称它有上界。peak.hi 因此不可计算，oom_verdict 落 undetermined， 并由判定阻碍分解（§10.3）逐条列出"要回答你的头号问题，先去标定这几个量"。

选哪一侧必须由机器定，否则这里是全篇最大的未受控自由度

一个看起来自然的选侧规则是"按该量对峰值的偏置方向定"。它不可执行，两个原因：

① 措辞二义。"偏置方向"既可读作"我们给的值偏向哪边"，也可读作"它把峰值推向哪边"， 两种读法在碎片上结果相反。

② 对绝大多数兜底量，真值方向本来就不唯一。以 fp32 主副本为例：公式 4×numel 本身确定， modeled 的来源是"框架是否真的建了这块"——没建 ⇒ 真值更小 ⇒ 我们是 upper； 建得更多 ⇒ 真值更大 ⇒ 我们是 lower。两个方向都能自圆其说。 更糟的是 C_eff 的减项（框架预留、池划分）根本不作用于 peak，规则的自变量不存在； 而碎片与通信时长按 §13.3 是非单调的，"偏置方向"这个概念对它们无定义。

后果：实现者对每个兜底量握有一个二选一，而这个二选一决定的正是头号输出—— 全选 upper ⇒ peak.lo 不可计算 ⇒ 永远说不出"会 OOM"； 全选 lower ⇒ peak.hi 不可计算 ⇒ 永远说不出"装得下"。 而结构性复活检测抓不到它：它不是字段、不是枚举值、不是转换算子。

所以规则必须是"保留能被算出的那一端"。它是唯一一条不需要知道真值方向就能执行的规则， 因而不引入新的自由度。本方案的兜底量全是非负字节，能算出的那端就是下确界 ⇒ 一律 direction := lower、interval := [已知下确界, 不可计算]。

一条看似更聪明、实则自相矛盾的规则

很容易改成"取使 oom_verdict 更难变确定的那一侧"：peak 的加项取 lower、 C_eff 的减项取 upper。判据 5 的方向看起来更顺。但它是错的—— 它按"该量落在算式哪一侧"分情况，而减法会翻方向：

C_eff = HBM − 减项。减项取 upper ⇒ 减项的 lo 不可算 ⇒ C_eff.hi = HBM.hi − 减项.lo 不可算。而"会 OOM"要的正是 peak.lo > C_eff.hi。于是两个 verdict 值同时不可达，G-M2 恒红。

"保留能算出的那端"没有这个毛病：减项的下确界是 0（非负）⇒ C_eff.hi = HBM 可算 ⇒ "会 OOM"仍可判定，而"装得下"不可判——这正是 §10.2b 那条不对称， 现在它是 P5 的推论而不是一条独立断言。

这不是把工具做废，而是把标定集变成真正的交付物。evidence.grade 从三个词变成一条产品路线： 标定一个量 ⇒ 它获得来源 ③ 的真实残差 ⇒ 它退出单侧 ⇒ peak.hi 向可计算前进一步。 判据 5 在此是顺向且构造性的：诚实使用不受罚，省事必然拿不到那句"装得下"。

P4 是承重墙：一条律解三处
  1. 抽象根生效：没有 P4，一个被抽象掉的 Linear 的激活字节 prod(shape)*sizeof(dtype) 的每个输入都来自源码根，算出来仍然精确——抽象只污染了"这是什么算子"，没污染"它产出多少字节"。 P4 把"若 n 根本不该存在，它的字节也不该被计"变成传播律。
  2. 通信字节嗅探门可满足：Pass_shard 的"失配处插 redistribute"是一个 self_certainty = modeled 的结构算子，own_roots = {replication(rule)} ⇒ 通信字节继承 modeled 与 replication 根，且根里没有标定根。门可满足且非平凡。
  3. 成员资格本身也要有区间形态：某个 storage 是否在 t* 存活若不确定，它对 peak 的贡献区间是 [0, size]——两端都可算，不落 P5 兜底。（兜底的"加项/减项"二分对成员资格没有自变量，不写死这一条会留一个无规则的格子。）
  4. 显存 ← 时间的耦合自动表达：overlap 开启时 Free 事件的时刻是通信时长的函数 ⇒ 该 Free 的存在位带标定根 ⇒ 受影响 storage 在峰值时刻的存活成员资格继承标定根。 "显存 provenance 是时间 provenance 的函数"这件事不需要额外机制。

连带定案：由 pass 合成的存储（fp32 主权重/主梯度、fp8 的 amax/scale 缓冲、梯度桶缓冲） 其存在位带 replication(rule) ⇒ 这些字节是 modeled 而不是 derived， 即便它们的字节公式本身是 numel × sizeof(dtype) 这样的平凡式。 判据是"这个节点为什么存在"，不是"它的字节怎么算"。

P4 的施行前提：每个 pass 必须填 own_roots，一个都不能空

P4 说"节点存在位的 Prov 来自产生该节点的 pass 的 own_roots"。 所以只要有一个 pass 没填，P4 在它产出的节点上就无法执行，那些字节会没有根、没有 certainty ——而实现者最自然的处理是"字节公式平凡 ⇒ 精确"，那正是 P4 要禁的事。 下表是必填清单，schema 断言"任何合成节点的存在位必有非空 own_roots"：

2.6 G-B1a 抽象残差：判据 5 唯一的构造性执行体

前面的机制只做到"可见"。而 certainty = modeled 本身不改变形状。 所以必须有宽度，而宽度不能是猜的误差棒：

抽象残差不是误差棒，是一个由被隐藏的源码机器算出的量。
设模块 M 被判成逻辑原子 A，readability(M) = FULL。对报告要输出的每个策略点 P：

  R_P := PE(M 的源码体, ModelSpec, EnvFacts, P)     # 在**真实策略**处偏特化，不经 π₀
  S_P := rewrite(A, P) 在 A 处产出的子图            # CoreIR→…→G4 这条**重建链**的产物

G-B1a（硬阻断）：shape 面 / arity 在 R_P 与 S_P 上不一致 ⇒ **阻断**
                （人声明的语义与源码直接矛盾，这不是抽象，是错误，不该被定价而该被拒）

抽象残差：其余各面逐项取凸包
  interval(A.q) := 区间算术(输入) ⊕ hull( S_P.q , R_P.q )      # **⊕ 叠加，不是赋值**
                 —— 赋值会吃掉输入自身的区间宽度，违反 P8（只升不降）   对 q ∈ {激活字节, 临时字节, workspace, flops, 通信字节}
三点必须讲清楚

① 为什么在真实策略 P 处比，而不是在 π₀ 处比两支残差。在 π₀ 处比 then/else 两支是错的—— else 支里的 AllReduce 会被 Pass_shard 名正言顺地重新插回来，把它计成不确定度是双计。 正确的对照物是"重建链在 P 处产出的东西"vs"PE 直接在 P 处读源码得到的东西"。

② 判断正确时残差为零。若 ColumnParallelLinear 真等价于逻辑 Linear + 我们的通信复刻规则， 则宽度 0，抽象不付代价。这是有意的——否则做对判断的人被惩罚，工具不可用。

③ 判断错时代价与错的大小成正比。若该"并行原语"偷偷多做了一次 scaling、少了一次 bias、 dropout 位置不同，则逐面不同 ⇒ 宽度正比于被隐藏的差异 ⇒ 经区间算术直达峰值。

G-B1a 的诚实定性（不等反驳，先说）

它是抽样门，不是证明。P 取自报告要出的策略点集，不是 guard 的全部取值。

更要命的第二层：共模误读会让它安静通过。S_P 由我们的复刻规则产出，R_P 由 PE 读框架源码产出。 两条路径形式上独立，但可以同源地错——写"ColumnParallelLinear ≡ 逻辑 Linear"这条抽象的人， 和写"列并行出口插 AllReduce"这条复刻规则的人，很可能是同一个人，带着同一份对框架的理解。 若这份理解错了，两边一致地错 ⇒ 残差为零 ⇒ 抽象免费通过，且报告显示它"经检验无残差"。

因此残差列禁止打印裸 0，必须打印 0（P_test 覆盖 N 点，非证明）。

2.7 比较、聚合与归因

cmp : Q[Real] × Q[Real] → Q3[Bool]
  a < b  ⇒ true         iff a.hi <  b.lo        （两端均可计算）
         ⇒ false        iff a.lo ≥  b.hi
         ⇒ undetermined otherwise，或所需的任一端不可计算

三条硬规定：① Q3[Bool] → Bool 的转换算子不存在（结构性复活检测断言之）； 需要 Bool 的消费者遇 undetermined ⇒ 阻断。② Sample[T] 上没有 cmp ——makespan 不能与任何容量或预算比较。③ 只有一端可计算时，只保留能被证明的那一侧。

归因口径固定为峰值时刻活跃集合分解：peak = Σ_{i ∈ live(t*)} size_i。三种聚合，性质不同， 报表必须分开呈现：

任何划分都要引入一个人为的主根优先序；而"如果我们把 X 判成 Y 是错的，哪些字节会变" 问的本来就是覆盖量，不是划分。这也正是可见性的准确形式： bytes_at_risk(judgment j) = coverage(abstraction(j))。

守恒的那一份由 certainty 三分承担——"provenance 闭合"这道门要的正是它，它被保住了。

t* 要在四个角上求

朴素做法是只在字节区间两端各跑一次 liveness。但 事件序也依赖时长估计（overlap 场景下 Free 时刻是通信时长的函数）⇒ t* 也随 时长区间移动。因此归因必须在 (字节端点 × 时长端点) 四角上跑 liveness； 退化到 2 次的条件是"该图无 timing_dependent 边"。

2.8 configured 根的三道闭合

configured 是八种根里唯一一个其叶子取值本身不承担可证伪义务的 （它定义问题本身，tp=8 无所谓真假）。注意这不是说"只有它允许精确"—— certainty 是算子的属性、不是根的函数（§2.2），源码根的量当然可以精确。 正因为 configured 的叶子不受证伪约束，它必须自带闭合——否则"把难算的量改名成规定量"就是零代价逃逸：把 MoE 每专家负载写成 ModelSpec.expert_load_per_rank ⇒ 根是 configured ⇒ 精确 ⇒ 区间塌点 ⇒ OOM 从三值变回二值。

3.3 策略分类表与 class_origin

分类表（哪个字段属哪一类、π₀ 取值是什么、谁重新引入它）是工具随框架版本发布的制品， 参与 digest。既然有出厂基线，用户的改动就是一个 diff，而 diff 是机器可见的：

因此八份 *Spec 的每一个字段都必须进这张表，各带 class 与 class_origin 两列——包括 DistOptSpec 与 PrecisionSpec。 表的结构（两列）是机制依赖的东西，具体行内容不是。

PolicyClassTable.row : { field, class, pi0, reintroducer, class_origin }
class_origin : tool_shipped | user_override      # 由与出厂表比对得出，**不可填**
这一格堵的是"改表"这条逃逸路径

把某个策略字段从 Π_extent 改判为 Model ⇒ 污点判据不再触发 ⇒ 阻断消失，该量仍精确。 前面所有机制对这条路径完全无效，因为改表不产生任何带 abstraction 根的节点， 它改的是根的种类。两条后果，都是机制：

(a) class_origin = user_override ∧ class = Model ⇒ 由该字段流出的每个量携带 abstraction(policy_reclassification, f@ver) 根 ⇒ 与"注册为原子"落进同一个报表口径、同一道 Θ 门。

(b) 扫描维度集合由类别机器导出，Model 不是扫描维度。 定义式必须是导出式而不是枚举式——枚举式会漏：把它写成 "Q2 表 ∪ RematSpec ∪ ScheduleSpec ∪ ImplSpec"就漏掉了 DistOptSpec 与 PrecisionSpec，而那两份恰好握着字节量最大的两个自由度 （free_policy 的几十 GB、master_weights 的 16 B/param）。 更糟的是它们也不会出现在 excluded_from_sweep 那一栏（该栏只列"因被改判而退出"的字段） ⇒ 作为自由度在报表上完全不可见。导出式使"新增一份 spec 却忘了加进扫描"这类复发在结构上不可能： sweep_dims := { f : f ∈ 任一 *Spec 的字段, 且 class(f) ∉ {Model, Env} } ——类型级导出，不是枚举。 把一个字段改判为 Model，它就从敏感性扫描里消失了，报表的 excluded_from_sweep 机器生成一行；同时它进入模型身份 digest，两次运行不再可比。

为什么不是"禁止改表"：禁止改表等于宣称出厂表永远正确，那是假的（新框架版本、新字段）。 允许改、但让改的人失去他来这个工具是为了得到的那个东西（这个旋钮的 what-if）， 是唯一既不撒谎又满足判据 5 的走法。

3.4 PolicyStateBinding：策略经函数访问器进入源码时怎么办

策略常常不是以 config.tp 的形态出现，而是经 get_tensor_model_parallel_world_size() 这类函数访问器、局部变量、闭包、模块级常量进入源码。 "表外任意 config.X ⇒ 阻断"在这些形态上不触发。

不采用「访问器 → 策略字段」映射表——访问器是函数，会有无穷多个，判据 3 过不了。 采用：把策略的状态源声明为事实源，让 PE 的既有污点机制自然覆盖访问器。

PolicyStateBinding : { 模块级限定名 → 策略字段, π₀ 绑定值 }
  例：<parallel_state 模块>._TP_WORLD_SIZE → policy(tp), π₀ = 1

PE **内联访问器函数体**（它是 PySub 里的普通 Python）
  ⇒ 读到已声明全局得到带 policy(·) root 的 Q ⇒ 污点自然流出，**不需要新机制**
局部变量与闭包不需要额外机制：它们的值由 PE 求得，污点随值走
BLK-UNDECLAREDSTATE 必须是「默认拒绝」，不能是「被写过才拒绝」

朴素设计是：读取任何"import 后被写过"的模块级可变全局，而它不在 PolicyStateBinding 里 ⇒ 阻断。 "被写过"由 PE 对源码树的赋值点集合静态判定。这个判定有一类结构性假阴性：

_STATE = {'tp': 1}          # 模块级绑定**一次**
def init(...): _STATE['tp'] = world_size    # 运行期只改**字典内容**，绑定从未被重写

于是"被写过"为假 ⇒ 不阻断 ⇒ PE 把 tp 读成 1，provenance 是 source / exact。 策略污点从未生成，policy-free 的断言平凡通过，而答案是错的——并且每一个指标都变好。

改法：判据画在读的一侧而不是写的一侧，并且"可变"的定义必须覆盖变异而不只是重绑定：

模块级名字 X 是「策略状态源候选」  ⟺  X 的绑定值在 import 之后**可能改变**

可能改变 :=  存在 X 的重绑定点（X = …、global X）
          ∨  存在对 X 所指对象的**变异点**（X[…] = …、X.attr = …、X 上的就地方法）
          ∨  X 逃逸到 PySub 之外   ← 无法证明不变 ⇒ **保守判为可能改变**

X 是候选 ∧ 被 PE 读取 ∧ 读值流入残差  ⇒  必须在 PolicyStateBinding 中声明，否则 BLK-UNDECLAREDSTATE

第二条堵住上面那个反例（下标赋值是变异点）。第三条是兜底，而它之所以可判定， 正是因为 PySub 是封闭语法子集：模块级对象只能经 PySub 里的语法构件被改动，变异点因此可静态枚举； 任何逃逸到 PySub 之外的路径本来就已经 BLK-SYNTAX。

为什么不是更粗暴的"读任何模块级全局即阻断"

那条会有一类结构性假阳性：框架里模块级全局极多（日志器、常量表、缓存、单例）， 其中大多数在 import 后从不改变。一律要求声明，会把 PolicyStateBinding 从闭集撑成开集——判据 3（非普适性）随之失守，而一张什么都要声明的表等于没有表。

上面的三条式判据把闭集画在可变性上而不是存在性上： 一张 import 后从不被赋值也从不被下标写入的常量表，可证不变 ⇒ 不需要声明； 而 _STATE 那种有变异点的，一定要声明。两边都不靠"我们没看见有人写它"。

3.5 配置规范化函数：在 PE 内求值，不建侧表

validate_args 一类函数填默认值、推导派生字段（padded_vocab_size 正是在这里被算出来的）、 做跨字段校正。它是被分析源码的一部分，不是新事实源；但必须在事实源清单里点名"模型配置的规范化入口"， 因为它决定了哪些字段有值。

它的输出分两路：

  • roots 无策略污点 ⇒ 直接进 CoreIR（绝大多数模型默认值属此，必须保留）。
  • roots ∋ policy ⇒ 不进 CoreIR。需要它的 pass 在自己的策略绑定处现场调 PE 求值。
为什么是"现场调 PE"，而不是导出一张 PolicyDerived 侧表

侧表方案（把 padded_vocab = ceil_div(vocab, 128·tp)·128·tp 抽出来存成条目）看起来更整齐， 但它有两个致命性质：① 一个手写条目与一个自动抽取的条目在数据上不可区分， 于是"任何算不出的量都可以写成一条派生规则"——它是"规定量"逃逸的同构物； ② 补一道"每个条目都能在当前 SourceAST 上重新推导出来"的门救不了它： 若该门就是重跑同一套抽取，它恒真；若它换一套推导，它不完备。而且它是加载期门去查编译期产物， 相位是错的。

现场调 PE 没有这些问题：没有可被手写的中间制品。规则始终留在源码里，谁需要谁去求值。 代价是同一个规范化函数会被求值多次——这是 PGRO 与 G-C3 本来就需要的能力（在任意策略处跑 PE）， 不构成新增成本。

现场调 PE 要补两道门，否则它打穿两条既有约束

① 授权闭包被打穿。规范化函数是跨字段的——pass 调它一次就事实上拿得到 tp，而"能力受限视图按字段授权"是层表签名 Pass_X(·, SpecA, SpecB) 为真的前提。且"该函数会读哪些字段"求值前不知道。G-E8（授权闭包门）：PE 求值时记录 used_fields（污点机制本来就在记），断言 used_fields ⊆ 该 pass 声明的授权字段集，越权 ⇒ 阻断。免费，且它同时给 sweep_dims 一个真实的载体。

② 规范化函数是普通 Python，可非幂等。同一环境调两次可能给出不同绑定，而 G-R3（pass 确定性）对它恒过——两次跑犯同样的错。G-E7（幂等性门）：同环境连调两次，输出绑定逐值相等，不等 ⇒ 阻断并指名该函数。配套：现场调用必须在隔离环境求值（纯函数：环境 → 残差 + 输出绑定，不改入参），按 (anchor, 环境 digest) 记忆化，每次调用进 runtime_pe_ledger 并参与编译产物 digest。

收益仍在：CoreIR 里只有 vocab_size（policy-free ✓），padding 规则来自源码而非人脑（保真度 ✓）， 且该表达式的 roots ∋ policy(tp) 全程可见（provenance ✓）。

4.1 PySub 与偏特化

4.2 四类 policy guard 与 PGRO

朴素的做法是要求每个 policy guard 的两支残差同构才允许在 π₀ 折叠。这个判据是错的， 证据就在它自己的例子里：通信包装 if world_size == 1: return x——else 支的残差含一个 AllReduce 节点，两支不同构，按该判据必须阻断；但这个 guard 显然应该放行， 因为 Pass_shard 本来就会在 placement 失配处插 AllReduce。

真实要求不是"两支一样",而是：

π₀ 残差必须携带足够信息，使下游 pass 能重建任意策略配置下的图。
guard 类特征放行义务（机器可判）不满足
G-irrelevant两支残差同构（如日志/断言分支）digest(res_then) == digest(res_else)降级到下三类继续判
G-reconstructible非-π₀ 支的残差正是某个 pass 会插入的东西PGRO（见下）BLK-UNRECONSTRUCTIBLE
G-absorbable两支算同一数学，只是粒度/实现不同注册一条逻辑原子 Op 后两支塌成同一节点，再判 digest 相等BLK-NOTABSORBABLE
G-semantic两支数学不同无义务——它根本不是策略（§3.2）改归 Model 变量
PGRO · 逐 guard 重建义务 
PGRO(g, p, v) :=  canon( Pass_X( residual(g @ π₀), p := v ) )  ≡  canon( residual(g @ p:=v) )

Pass_X 是分类表"谁重新引入它"一列指定的那个 pass——这一列从此不是说明性文字， 而是 PGRO 的形式参数。canon(·) 是规范化：α-等价 + 确定性拓扑序 + 已注册的代数恒等， 规则集必须闭且版本化，且不得含吸收策略常量的化简。

不满足 ⇒ BLK-UNRECONSTRUCTIBLE，工单附 diff，并指明三条补救之一： 补 pass 能力 / 该字段其实是模型变量 / 该字段其实改变数学。

PGRO 的价值：把一个端到端的义务拆成可归因的局部义务

Π_extent 的 guard 绝大多数落在 G-reconstructible，而不是 G-irrelevant。 要求它们过"同构"判据，等于给它们套了一个它们按定义就过不了的义务—— "π₀ 折叠几乎处处非法"这个结论的根源在此。

两个典型反例都因此消解：if recompute_granularity == 'full': checkpointed_forward(...) ⇒ Pass_remat 的职责恰是"结构复制 + saved 边改接"； if sequence_parallel: scatter_to_sequence_parallel_region(...) ⇒ scatter-to-SP-region 就是一次 placement 重分布，Pass_shard 在失配处插 redistribute 正是此事 （不需要把 embedding 注册为原子）。

更重要的是：PGRO 是"重建保真度"这个端到端义务在 guard 粒度上的分解—— 它把一个不可归因的整体义务，拆成一组局部、可定位、纯静态可判的义务， 且每一条都指着一个具体的 pass 和一个具体的策略取值。

PGRO 的边界，以及它最大的风险

边界：PGRO 只能证明"pass 重建出的图 ≡ 源码 else 支写的图"。 它不能证明"源码 else 支写的图 ≡ 框架真机上真正执行的图"——后者只能由 op 级 time 序列兜。 静态的一半做实了，真机那一半仍在原处。

风险：判定完全依赖 canon 的规范化能力。canon 太弱 ⇒ 大量本应通过的 guard 因表面差异被误判为不可重建 ⇒ 假阻断泛滥，用户被迫去"补 pass 能力"来迎合规范化器， 反而把错误的实现写进 pass；canon 太强（加入过多代数恒等）⇒ 两个真正不同的图被判为相等 ⇒ PGRO 静默放行一个错误的重建，这是本方案最怕的失效模式。

规则集闭且版本化是必要条件，但"规则集是否恰好够用"没有任何判据，只能一条条撞出来。 这一条进能力边界（第 14 章）。

4.4 逻辑流程

  1. 从 ModelSpec 定位入口；在 PE 内求值配置规范化函数与全部校验断言（§3.5–3.6）。
  2. PE 在 π₀ 下偏特化：逐个内联可展开调用，按污点分类每个 guard（§4.2），逐 guard 履行放行义务。
  3. 识别重复结构（层、专家）折叠成 RepeatRegion，count 保持为符号。
  4. 每个原子调用与 S1 快照绑定 ⇒ SemanticId；未绑定 ⇒ 阻断 + 生成骨架（第 11 章）。
  5. 按 shape / dtype / storage 三面求值，得到 TensorValue 与 Storage。
  6. 校验 G0 不变量：无 policy root、无 opaque、每输出恰一条存储规则、alias 链无环无悬空、side-effect 算子未被跳过。

6.4 原子性、类型系统与禁止项

Op 类型必须拆到原子级。不推荐把 14 种视图语义合并为一个 View 类型再在代码里二次分派 ——那相当于重新解析配置中已有的信息，并迫使不同语义共用一条反向规则。

类型用途例

组合子不等于「Op 关联了代码」

rel: reshape 里的 reshape 是表达式求值器的原语，与任何具体 Op 无关 ——正如在配置中写 2*x 并不意味着配置关联了代码。判据很明确：组合子可以跨 Op 复用， 而 Op 独有的知识只有"关系名 + 参数来源 + 守卫"，全部以数据表示。

组合子构成闭集：same_as · broadcast · replace_last · bmm · halve_last · reshape · permute · swap_axes · squeeze · expand_dims · concat · stack · split · chunk · slice · tile · literal · range_len · index_compose。 引用不存在的组合子 → 加载即阻断。

每个组合子必须声明其归约类（是否可交换、是否幂等、单调方向），否则 P6 的方向传播与 P8 的 property test 无从执行。这一条很容易漏：组合子表看起来只是一张关系名清单， 归约类却是它必须携带的第二列。
另：闭集里不得有 declared 这样的"组合子"——它不是关系，是一个万能出口，判据 3 不过。

禁止：循环、递归、赋值、可变状态、文件/网络/环境访问、import、用户自定义函数、 运行期改注册表、用缺省值替代未声明项。

为什么 exact 必须对出厂内置开放——否则整套惩罚机制自锁

把"注册域拿不到 exact"写成无条件的，看起来是最严的堵法，实际会让方案在自己的门下启动不了。 推理只有三步，每步都是本方案自己的规定：

  1. S1 是算子语义的唯一词典 ⇒ 每个张量的 shape / dtype / storage 都由某个 RegisteredOp 求值（§4.4 步骤 5）。
  2. 若 RegisteredOp 一律不许 exact，由 P2 ⇒ 全链没有一个字节是 exact； 再由 P3 取最弱 ⇒ 全链 evidence.grade 恒为 reconstructed。
  3. 又由 §2.4 的分派表（若它字面适用于全部注册项）⇒ 连 Reshape 都背 abstraction 根 ⇒ θ_abs 的分子 ≈ peak ⇒ 恒真 ⇒ VERDICT-WITHDRAW 恒触发 ⇒ oom_verdict 恒 undetermined ⇒ G-M2 在第一天就是红的。

病根是把两类注册项混为一谈。要堵的是"用一次注册来消化一次阻断"—— 把 ColumnParallelLinear 判成逻辑 Linear，那是人的判断。 而 Reshape「单缺维由元素数守恒唯一确定」是工具出厂就带的算术事实，它不消化任何阻断。 两者的区别机器可判且不可伪造：origin.block_code 是不是 null ——它由 PE 在注册产生的那一刻写入。

于是三条限定同时成立才给 exact：出厂内置（不是阻断的产物）、 readability = FULL（我们真的读得懂它）、单算子粒度（不是把一坨东西打包）。 ColumnParallelLinear 由阻断产生 ⇒ block_code ≠ null ⇒ 永远拿不到 exact， §2.1 的病灶不复发；而 native_exact_ledger 参与 digest，出厂表被改动一样上首页。

为什么是"递减"而不是"必须为 0"，以及为什么 G-Z1b 没有断言

"新增条目数必须为 0"是假命题——新模型用了新算子族本来就该新增注册。一旦被现实打脸， 就只能靠人工例外来救，而人工例外正是要消灭的东西。递减是同一假设的真的可证伪形式： 算子族有限，词汇必须收敛。

G-Z1b 给不出真的断言，所以选择说没有，而不是假装有。 把本该记为词汇的东西记成抽象（或反之）来做数字——做不到，readability 由 PE 在阻断时刻写入。

连带的诚实结论：本方案没有"到此为止、可以宣布收敛"的硬停止条件。 G-Z1a 是证伪条件（不递减 ⇒ 基本假设被推翻 ⇒ 停止实施），不是完成条件 （没有任何 k 使我们能宣布注册工作结束）。旧的"必须为 0 + 人工例外"同时冒充了这两者， 那是它最初就错的地方。

Chapter 10两后端与报告

10.1 两个只读后端

显存后端只消费 MemoryEventView：按事件推进，依据内存池与对齐规则模拟申请释放， 给出已分配 / 已保留峰值区间与首次失败证据。结束前终审：不得残留未释放的非持久实例。

时间后端只消费 ResourceRequest 与硬件/profile 快照，两级离散事件仿真（段内多流 → 全局调度）。 定价分级回退：命中兼容实测 → 形状/类型插值 → 已标定族模型 → 理论 roofline。注意区分两种失效——roofline 级是「该算子族从未建立过标定域片」时的初始定价（合法，落 P5 兜底单侧）；而「越域」是「有域片但参数落在域片外」（阻断）。把两者压成一条线性回退链，会与 G-X3「域片内标定点集非空」相冲突，使无标定的 roofline 级恒不可达； 每一级都是一个 self_certainty = modeled 的算子，参数不完整时阻断， 绝不静默降级为零成本或纯带宽模型。

后端的独有不变量：零新事实

后端不得引入新的 root 种类。roofline 时长 = flops / peak_flops 的两个输入都精确， 但它经过一个 self_certainty = modeled 的算子 ⇒ 结果是 modeled / reconstructed， 不是 derived。allocator 的池划分/对齐/split 同理。

一句容易被误读的话："显存链上没有任何一个量是查表得来的"——它成立（确实没查表）， 但它不等于"显存链上都是事实"：显存链上有大量量是我们对 allocator 的复刻， 属 modeled / reconstructed 而非 derived。

inf_interleave  := max over 节点 n ∈ G4 偏序 :  Σ_{s : def(s) ⪯ n ⪯ lastuse(s)} size_s
                   s 取值范围 = **StorageId**（alias 等价类），不是 TensorId
sup_interleave  := Σ_streams peak_s

# 合成：先在四角上各取一次，再对三轴取包络
peak_allocated.lo := min over 四角 :  inf_interleave( size := size.lo )
peak_allocated.hi := max over 四角 :  sup_interleave( size := size.hi )
peak_reserved     := peak_allocated ⊕ 碎片 ⊕ 池划分        # 二者有结构性上界（P5 ⑤）

peak_interval     := peak_reserved                          # **对外唯一字段**，其余是中间量

inf_interleave 的论证：任何线性化都必经过 n，届时上式集合中的每个 storage 都已分配且未释放 ⇒ 跨全部交织的合法下界。复杂度 O(节点数 × storage 数)，不是最大团问题。

为什么必须把三条轴分开写

它们回答的是三个不同的问题：交织轴问"真机会走哪条线性化"、字节轴问"每个量本身有多不确定"、 时刻轴问"峰值发生在哪一刻"。三者**互不蕴含**——字节全精确时交织轴仍有宽度， 交织唯一时字节轴仍有宽度。

不分开写就会出现一类很难发现的错：把交织轴的下确界直接当成对外的 peak.lo。 那是错的——前者是在某一组字节取值下算的，而 peak.lo 要求字节也取 lo、 且 t* 要在四角上取遍。合成式把这三步显式化，对外只暴露 peak_interval 一个字段。

但它不是无条件下界，两个条件必须写死
alias 判定按 P4 必须污染每个 storage 的字节，不止 inf_interleave

alias 等价类决定一个 storage 实例是否存在——这严格落在"存在位下传"的射程内。所以每个 size 都背 replication(alias_rules)，不是只有下界构造背。

连带必须一并接受：修好之后该根的 coverage ≈ 100% ⇒ §10.5"按 root 覆盖八行"退化为"有一行接近满"。所以那张表必须改按 replication 的 rule 粒度打印（alias_rules / collective_rule / bucketing_rule …），而不是按根的种类打印。根种类是闭集八值，规则名不是——后者才是"去改哪一条"的粒度。

条件一 · alias 等价类必须正确。若两个实际共享存储的值被判成两个 StorageId， 它们会被各计一次 ⇒ inf_interleave 偏高 ⇒ 可能产出假的 OOM 断言。 而 alias 判断恰恰是完全无验证手段的那一格（§5.1）。因此 inf_interleave 携带 certainty = modeled、roots ∋ replication(alias_rules)——它是一个条件下界， 不是一个定理，报表必须这样标注。

条件二 · 求和只能包含 Free 由结构边决定的 storage。若某 storage 的 lastuse 由 timing_dependent 边决定，则 ⪯ 不再是纯结构偏序，"任何线性化都经过 n"的论证失效。 这类 storage 一律从 inf_interleave 的求和中排除（保守，使下界更松，方向正确）。

排除之后还剩多少——它不是一个近乎空的和

被排除的是"释放时刻取决于通信时长"的那些：overlap 下的通信 buffer、prefetch 中的已 gather 参数、 在飞的梯度桶。剩下的恰好是量最大的两块：

  • 持久存储（参数、优化器状态、fp32 主副本）在整个 step 内没有 Free ⇒ 恒活 ⇒ 恒在和内。训练态下这一块是 16 B/param 量级，本身就是最大的单项。
  • 激活的 lastuse 是结构依赖（读它的那个反向节点），与时长无关 ⇒ 保留。

并且参数本体的字节是 source 根、exact、区间为点， 所以inf_interleave ≥ Σ 参数字节 无条件成立——这已经是一个非平凡的、 可被真机 OOM 事实证伪的断言。排除 timing_dependent 削弱的是精度，不是存在性。

为什么必须补下界，哪怕它这么弱

ScheduleSpec 声明的那个交织下的峰值不是跨交织下界（真机可能走别的交织）， 把它当下界用会产出假的 OOM 断言——正是"给一个假装确定的答案"。 在前提 P-peak 之下，peak_allocated.lo（其构造是 inf_interleave）是显存链上唯一能产生"可被真机 OOM 事实证伪的断言"的构件。

把碎片算进来之后，两个方向不是对称的。这一小节是全篇结论最硬的一处，必须单独讲。

先解决一个类型问题，否则下面整节都没有对象可谈

oom_verdict 是一次比较：cmp(peak, C_eff)。而 C_eff = HBM_total − framework_reserve − 池划分开销，其中池划分开销 按 §13.3 属于非单调维度——非单调量的产物是 top-N 扫描得到的样本极值， 按 §2.3 的类型定义那就是 Sample[Int]。

解法只能是让 C_eff 恢复成 Q，即给它的两个减项各一个界而不是一个样本。 碎片与池划分都有结构性上界（P5 来源 ⑤）：它由 allocator 的池划分规则与 G4 的事件序组合算出， 形如「碎片 ≤ 活跃分配块数 × 最大对齐/分块粒度」，不依赖任何扫描、任何标定点。 它偏宽 ⇒ undetermined 更常见 ⇒ 正是判据 5 要的方向； 而档 C 的第一类维度随之从"必须逐维 OAT"变成"已被界覆盖"，扫描维度反而更少。

这是"判据 5 成功"还是"方案失效"？——需要一条机器判据来分

P5 兜底取单侧 + Θ 门触发 VERDICT-WITHDRAW，两者叠加确实可能让工具恒输出 undetermined。而恒 undetermined 与"什么都不输出"在决策上等价 ⇒ 方案失效。 所以需要一条可用性下限，把"严格"与"做废"分开：

G-M2 · 可用性下限门

CI 必须存在至少一个洁净配置 fixture ——全部算子 Tier 1、无手写 placement、 无 assumed 负载、无 user_override、碎片模型已标定 —— 使得 oom_verdict ≠ undetermined。

若连洁净配置都判不出来，说明惩罚机制把工具本身吞掉了，此时该修的是机制而不是配置。

为什么这条判据是对的：判据 5 要求的是"用了逃逸就变差"，不是"什么都不用也拿不到答案"。 洁净配置是逃逸的零点——它拿不到确定结论时，变差的就不是逃逸的代价，而是方案的底噪。 G-M2 把这个区别变成一个能变红的 CI 断言，而不是一句争论。

10.3 oom_verdict : Q3[Bool] 与判定阻碍分解

容量本身有 provenance：C_eff = HBM_total − framework_reserve − 池划分开销， 其中 HBM_total 是 transcribed，后两项是 modeled / reconstructed。所以是区间对区间：

oom_verdict : Q3[Bool] :=
  false（装得下）  iff  peak.hi ≤ C_eff.lo
  true （装不下）  iff  peak.lo >  C_eff.hi
  undetermined     otherwise，或任一端不可计算
undetermined 必须是类型，不能是标签

强制附带判定阻碍分解：给出最小的量集合 S，使得把 S 中每个量固定到其区间某一端后 verdict 变确定；逐条列出成员、其 roots、其 evidence.grade、其宽度贡献。

它必须分成两段，因为要求用户做的动作不同：

段内容排序键用户要做的
第一段 S_∞ ∩ live(t*) 的全集——端点不可计算的量。它们是合取必要条件， 没有"最小集"可言，也没有全序（宽度不可计算 ⇒ 不可比较）。输出其基数 blocking_set_size coverage_bytes 去获得一个界（标定、或补一条可算的结构性上界）
第二段 仅当 S_∞ ∩ live(t*) = ∅ 时才有意义：对剩余的可计算宽度跑贪心。 此时在固定 t* 上 peak 是和、宽度可加 ⇒ 按 width(size_i) 降序取前缀确为精确最小集，O(n log n) width 去收紧一个界

为什么不能合成一段：贪心的"精确"论证前提是宽度可比较。只要有一个量的端点不可计算， 它的宽度就没有数值，全序不存在，贪心退化为"最小集 = 全集"——一个恒等于全部量的清单没有指导价值， 而且它会把真正的第二类问题（某个已有界但太宽的量）淹掉。

为什么不是只报一个百分比：百分比回答不了用户的下一个动作。最小集直接说"要回答你的头号问题， 先去标定这 3 个量"——它把 undetermined 从坏消息变成一张工单。这正是判据 5 想要的： undetermined 比二值答案难看，但它是可行动的难看。

不可绕过性

undetermined 不可被 assumed 声明消除：声明一个 assumed 量只能把区间从 "不可计算"变成"单侧开口"，两者在判定表里同样落进 undetermined 或至多单侧结论。 没有任何一条补救能把 undetermined 变回 false（装得下）而不真正收紧区间。

并且 Q3[Bool] → Bool 的转换算子不存在：任何需要 Bool 的消费者 （"自动挑一个装得下的配置"这类）遇 undetermined ⇒ 阻断。

10.4 VERDICT-WITHDRAW：惩罚挂在头号输出上

峰值在 schema 中只有区间形态、没有标量形态（§1.4 不变量 10）， 所以"撤回点估计"这类惩罚是空动作——从来就没有点估计可撤。惩罚必须挂在头号输出上：

# 分子：真正的**并**（逐字节判定"带这两种根之一吗"），不是两个覆盖量相加
# 分母：与分子同口径的 size.lo 之和 —— **恒可计算**，且比值恒 ∈ [0,1]
judged := Σ_{i ∈ live(t*) : {abstraction, declared_semantics} ∩ roots(size_i) ≠ ∅} size_i.lo
base   := Σ_{i ∈ live(t*)} size_i.lo

    judged / base                                 > θ_abs        # 四角上取 max，并打印四角取值
  ∨ timing_dependent 扫描观测范围宽度               > θ_TD
  ⇒ oom_verdict := undetermined（**无论区间落在容量的哪一侧**）
     且首页打印触发项、其实测比值与当次 Θ 取值

为什么这样比"撤点估计"强：它直接打在用户来这里要的那句话上，而不是打在一个中间产物的呈现形态上。

分子与分母各有一个必须写死的细节，否则这道门要么恒真要么不可判

分母不能写裸 peak。peak 是区间，且随四角移动。写裸的会有两种后果： 取 hi 端则它常常不可计算（§10.2b 的 S_∞）⇒ 比值是 Q3 而不是数 ⇒ 需要 Bool 的消费者按 §2.7 硬规定 ① 阻断；取 lo 端而分子取别的端， 则比值失去意义。钉死为分子分母同口径的 size_i.lo 之和：恒可计算、比值恒在 [0,1]、 四角上取 max 并打印四角取值。

分子必须是"并"，不能是两个覆盖量相加。roots 是集合、`⊔ = ∪`、 且 P8 保证只升不降 ⇒ coverage 沿数据流饱和：同一层里既有被抽象的模块、又有无 AST 的融合 kernel 时，同一批下游字节会同时带上两种根，被两个 coverage 各计一次。 相加 ⇒ 比值可以 > 1 ⇒ 门恒触发。逐字节判"带这两种根之一吗"才是并。

连带：同样的饱和使 abstraction_ledger.coverage_bytes 与首页"按 root 覆盖八行" 趋近于"每行都接近 100%"、零信息。所以两处都要并列打印第二列 own_coverage(r) := Σ_{i : r ∈ own_roots(producer(size_i))} size_i—— 只算"这个根是在哪个节点上产生的"，不算它传播到哪。 own_coverage 回答"我该去改哪一个"，coverage 回答"如果它错了最坏波及多大"， 两个问题都要答，但不能混成一个数。own_roots 是 P1 里已有的概念，零新构件。

这里没有一条"证据等级占比"的阈值，是有意的

一个自然的补充是再加一条 (reconstructed + vendor_documented) / peak > θ_evd。 它必须不存在，因为它是一道恒红的门：

本方案的显存链大部分由复刻构成——allocator 行为、通信插入规则、分桶算法、重算克隆、 精度主副本，全部是 replication 根、evidence.grade = reconstructed。 其中重算副本在全层重算下就是全部激活字节。所以该比值对任何小于 1 的阈值恒真。 而恒红的门与恒绿的门一样坏——它不携带信息，且会把 VERDICT-WITHDRAW 变成常态， 使真正的触发原因（人工判断占比过高）被淹没。

"是复刻"不是病，是这类仿真器的常态；"没有残差来源"才是病。 而后者已经由类型层处理：落 P5 兜底 ⇒ 单侧 ⇒ peak.hi 不可计算 ⇒ undetermined， 不需要任何阈值。能在类型层消除的阈值就不该归 Rule Θ（§0.2 判据 4 的正确用法）。

归因口径的三条论证

先排除一条**不能用**的：「活跃集合在真机 allocator dump 里可观测」在前提 P-oracle 之下为假。 可用的是这三条：

① 守恒性：Σ 各部分 = 报告的那个数，无残差、无重复计数、无基线。 "对增量的贡献"需要一个基线，基线任意 ⇒ 不可证伪，且不守恒。这一条独立于任何真机数据。

② 可证伪的对象是模型而不是真机——"对模型可扰动"： ∀ i ∈ live(t*)，把 size_i 加 δ，报告峰值必须恰好变化 δ； ∀ i ∉ live(t*)，变化必须 ≤ δ。这是一条机器可检的 property test， 会因为"归因实现与峰值计算用了两条不同的求值路径"而失败。 诚实的范围声明：这使口径对归因实现可证伪，不使它对显存模型可证伪。

③ 目的相符：归因的用途是决定去改哪个输入，这是纯内部用途。 "真机的峰值由哪些量构成"这个问题在前提 P-oracle + P-peak 之下没有人能回答， 因此把它设成归因的目标本身就是错的。

11.2 闭环流程

  1. 发现未绑定调用 → 阻断，输出：符号、各输入形状与类型、赋值目标、三个注册域的查找结果。
  2. 生成骨架：只填写可从调用证明的信息（selector、输入、attrs）， 其余字段全部保留 REQUIRED 占位；origin.readability 由 PE 在此刻写入，用户不可改。

骨架里不含源码文件与行号——那些只出现在诊断输出，避免用户配置与源码位置耦合。

11.3 补救模板必须声明 clean_effect

前面所有机制治的是当下已知的逃逸路径。下一条补救被加进来时，同样的病会原样复发 ——这在本方案的演进史上已经发生过一次（一个被删掉的"可接受差异"清单， 换个名字以"豁免通道"的形态装了回来）。所以需要一条全称律。

洁净度向量（闭集五元，全部机器计算，均不在用户的 *Spec 里）：
clean(Report) := (
  c1 = 峰值中 certainty = exact 的字节占比,
  c2 = |sweep_dims|,
  c3 = oom_verdict ≠ undetermined : Bool,
  c4 = −(abstraction_covered_bytes + declared_semantics_covered_bytes),   # 取负，越脏越小
  c5 = 被独立对照门覆盖的算子占比
)

L-mono（不可逆脏化律）：对任意补救 r（向输入集增加一条声明）
    clean( Report(I ∪ {r}) )  ⊑  clean( Report(I) )     逐分量偏序
    **且至少一个分量严格下降**

G-B0（补救单调性门，机器执行）：
    每条补救模板在 schema 中必填 clean_effect : Vector[5] of {不变, 下降}，且至少一项为「下降」；
    CI 对每条模板用**合成 fixture**（一段触发该 BLK-* 的 PySub 片段 + 施加补救）实跑两次报告，
    断言实测方向与声明一致。合成 fixture 不需要框架源码。
为什么是这条，而不是"逐条审查新补救"

逐条审查是流程；clean_effect 是 schema 必填 + CI 实测，是机制。 而且它把判据 5 从一句评审口号变成一条可以对未来的补救执行的断言。

G-B0 自身不放行任何东西，它只拒绝"声明与实测不符"的补救模板，因此它不是新逃逸口。

11.5 被禁止的通道形态

前提 P-noexc 不是一句原则，它有一份可机器检查的形态黑名单。以下任何一种出现在 schema 里， G-X1 即拒绝——它们的共同点是"最终由人拍板，且拍板结果是放行"：

形态为什么它是逃逸而不是治理替代物
豁免 / 例外条目给唯一的对照物配一个绕过通道，等于取消它 归属判定：把差异分成若干类，每类各有出口，没有一个出口是"放行"（§7.2）
"可接受差异"清单无上限的初值 + "单调不增"是空约束 差异进答案的形状（区间并），不进清单
告警 / 标注标签不是类型，下游不受约束 ⇒ 判据 2 不过阻断，或改变输出的类型
"经评审后生效"流程不是机制；评审不进 CI，也不进 digest 机器可判的出身标记（如 class_origin）+ 自动的能力削减（§3.3）
"标称值" / 中位数方向使区间塌成点，而塌点正是要防的那件事 direction ∈ {upper, lower}，必然单侧开口（§2.3）
未匹配项的忽略清单可被调宽到吃掉真实差异，且调宽不改变答案形状 逐条计数并进区间上界；反方向硬失败（G-T1）
对照映射里的逐 op 例外同上，且更隐蔽——它藏在"对照怎么做"里而不是"结论是什么"里 ψ 只允许两种动作，封闭可查（G-X5）
使用者可设的门限可配的阈值一律使答案变好（放宽 ⇒ 降级更少触发） 类型层消除；消不掉的归 Rule Θ，工具常量、进 digest、上首页
为什么要把它列成表，而不是只写一句"不许开例外"

因为同一个东西会换名字回来。删掉"可接受差异"之后，它可以叫"豁免"；删掉"豁免"之后， 它可以叫"待确认项"。按名字禁是禁不住的，按形态才行——而上表的每一行都对应 G-X1 里的一条字段名/枚举值断言。

12.1 元门：先把"门"这个词管住

其余 42 道里，17 道用我们自己写的对照物（源码文本、图自身、快照）检模型事实， 27 道是自律门——它们防的是"方案被改坏"，不是"模型算错"。自律门有价值， 但把它们和外部裁判并进同一个"40 道门"里报出去，就是在制造安全感。

这也是 第 14 章能力边界 E 的门体系侧投影： 显存链的 39 道门全部是自洽性检查——能抓实现错、抓规格自相矛盾、抓与源码文本不符， 抓不到"我们对框架的整体理解是错的"。

数门的判据：共用 oracle ≠ 是更弱的断言

很容易把读同一份数据的两道门合并计数。这是错的，反例就在本表里： G-N2（桶数等于真机归约 op 数）与 G-T1（op 序列是真机的保序子序列） 读同一条 trace，但分桶欠预测时——我们算出 4 个归约、真机有 6 个——我们的序列仍是合法子序列 ⇒ G-T1 绿；而计数不等 ⇒ G-N2 红。

子序列断言是非对称的（只惩罚"多"，不惩罚"少"），等式断言在该投影上严格更强。 数门的正确判据是「能否构造一个缺陷使 A 红而 B 绿」，不是「它们读同一份数据吗」。

14.2 能力边界 E

四处最弱重叠在同一格，因此把它写成一条命名性质，而不是四条散落的自曝 
边界 E：
  设 U := { 源码不可读的对象 } ∪ { 不改变 op 序列、也不显著改变时长的差异 }
  对 U 内的一切，本方案提供：
      (i) 一个不可声明的根、(ii) 一个证据等级、(iii) 一个覆盖字节计数、(iv) 一个 Θ 门
  **不提供**：任何构造性残差、任何独立对照物、任何证明。
  报表首页必须打印两个数（**不是一个**）：
      size_unverifiable       := Σ_{i ∈ live(t*) ∩ U} size_i.lo  /  Σ_{i ∈ live(t*)} size_i.lo
      membership_unverifiable := |{ i : i 的存活成员资格不确定 }| / |live(t*)|
`U` 必须是**代数上可判定**的量集，不能是一个反事实差异集

把 `U` 写成「不改变 op 序列、也不显著改变时长的差异」有三个毛病： 「显著」是隐藏阈值；反事实差异不是一个可枚举的对象；而且按字面它覆盖全部成员资格通道 （liveness 判断从不改变 op 序列）⇒ 占比恒 100%，这个数没有信息。

改为三条现成 schema 字段的并集，全部逐量可判定、无阈值：

U := { q : roots(q) ∩ {declared_semantics, abstraction} ≠ ∅ }
   ∪ { q : evidence.grade(q) ∈ {reconstructed, vendor_documented} }
   ∪ { q : own_residual(q) 无机器来源（即 q ∈ S_∞） }

并且必须拆成两个数：字节口径与成员资格口径的分母不同（字节 vs 实例数）， 量纲不同、可行动的方向也不同——前者要去标定一个量，后者要去确定一条生命周期。 混成一个数会让其中一个永远淹掉另一个。

去重规则明写：U 是量集不是根集，size_i 在分子里只计一次 （三条子句命中任意一条即入集），因此占比恒 ∈ [0,1]——这与 coverage（非划分、可 > peak） 是两种不同的口径，不可互换。

凡"源码读不到内部"或"唯一 oracle 覆盖不到"的地方，全部构造性保证同时失效，只剩阈值、抽样与披露。 这不是四个独立缺陷，是同一条能力边界的四个投影：

投影内容
代数侧readability = NONE 的那一半（融合 attention 的 workspace 与 captures、 MoE dispatcher、通信 kernel、allocator 的池/对齐/split）没有机器残差。 G-B1a 需要 PE 读得到源码体，那里读不到
门体系侧改写链有 oracle，存储模型没有 oracle。 且 op 身份映射表（真机算子名 ↔ 我们的 semantic_id）本身是又一张人工映射表， 它若被调宽，最强的那道门会静默退化为恒真门
支点侧canon(·) 太弱则假阻断泛滥、太强则静默放行错误重建， 而"规则集是否恰好够用"没有判据
规模侧对账表四个输入数全是推的且结论乘性敏感； top-N 截断用 OAT 的产物决定 OAT 扫哪些维，是循环论证

这条比四条分散的自曝强在：它给出了那一格的边界定义与一个必须打印的数， 于是"我们在哪里瞎"从散文变成一个可以逐版本比较的指标。

14.3 其余诚实边界

本设计明确做不到的事
  • 没有停止条件。G-Z1a 是证伪条件（不递减 ⇒ 基本假设被推翻 ⇒ 停止实施）， 不是完成条件——没有任何 k 使我们能宣布注册工作结束。
  • alias / in-place / 存储复用判断无验证手段。它既不改变 op 序列、也几乎不改变时长， 在唯一的 oracle 上结构性不可见。判错的后果是显存的一阶量，且它是 peak_allocated.lo 的前置条件。
  • liveness 与释放时机无验证手段。调度的 Alloc/Free 语义、allocator 的碎片模型整块处在盲区。
  • 融合 kernel 的 captures（Tier 2）只有惩罚没有验证。 "验证力度与风险大小成反比"这个病被降级为一个代价单调的宽区间，未被解决。
  • workspace_bytes 无验证手段。证据源只剩厂商文档/反汇编/显存标定， 而显存标定按 G-X4 只能进常数位、不能进 oracle 位。
  • placement 面的规格错误（区别于实现遗漏）在无对照 trace 的部署下无验证手段； 即使有 trace，若错误既不改变通信种类也不改变个数（两轴等长的切错轴），仍看不见。
  • PE 共模误读中"既不改 op 序列、也不改时长"的那一类（attrs 里的一个数值、某个 storage 的 dtype 判错）： G-C3 因两边共用同一个 PE 而对共模误读结构性免疫，op 序列门只看 op 身份。
  • G-T2 的形状检出是相对标定循环的：时长→形状的推断走的是我们自己的成本模型的逆。 若成本模型与形状模型同向偏差，残差可以互相抵消而门通过。
  • 桶的内容（哪些参数进哪个桶）无验证手段——只要桶数对，内容错也过。
  • 不逼出补偿算子的释放策略差异无验证手段。释放是主机侧动作，在 O 里不存在 ⇒ free_policy 的 at_step_end 与 never 结构性不可分辨， 而二者的峰值差是全部参数字节量级（§8.2）。
  • 在 allocator 碎片模型标定之前，"装得下"这个结论在原理上给不出来（§10.2b）—— 这不是精度问题，是可判定性问题。
  • 覆盖面：不承诺一次覆盖所有模型族；未覆盖的层类型必须显式阻断，不生成空层结果。
为什么把这一章写这么长

因为在前提 P-oracle + P-peak 之下，这份方案能提供的最有价值的东西，不是"这个数是对的"， 而是"这个数在哪些地方可能是错的、错了多少、以及要花多少代价才能不错"。

第 2 章的代数、第 12 章的门表、第 10 章的三值判定，全部服务于同一件事： 把"我们不知道"从一句免责声明，变成一个带类型、带计数、带阈值、能沿着计算链传播到头号输出的对象。

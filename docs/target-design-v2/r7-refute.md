# 3. 成立的新反例（非相乘类）

## C1 · `not_applicable` **没有载体**：F4 的修复在类型层就落不下去

| 出处 | 原文 |
|---|---|
| §2.3 行 241 | `evidence  : Evidence \| ⊥            # certainty = exact 时为 ⊥` |
| §2.3 行 269 | `Evidence := { grade ∈ {calibrated < vendor_documented < reconstructed, not_applicable}, ref }` |
| §2.3 行 272 | 「`not_applicable` 专给 `certainty = exact` 的量（**它们的 `evidence` 是 ⊥**）」 |

**行 241 与行 272 不能同时为真**：若 `exact ⇒ evidence = ⊥`，则这些量**根本没有 `grade` 这个字段**，`not_applicable` 永远不会被任何量取到 ⇒ 它是一个不可达的枚举值。

而 F4 引入它的**唯一理由**（行 276-277）是：「参数本体是 `source` 根、`exact` ⇒ `evidence = ⊥` ⇒ 不属三级中任何一级 ⇒ 三行之和 < peak」。⇒ **诊断完全正确，药加了，病没治**：加一个不可达的枚举值不会让参数本体进入任何一行，`Σ 各行 < peak` **原样成立**，"划分，守恒"仍然是假的。

**最小修补（一行）**：行 241 改为 `evidence : Evidence`，`certainty = exact ⇒ evidence = { grade: not_applicable, ref: ⊥ }`。删掉"`⊥`"这个取值，否则四值是装饰。

## C2 · F4 破坏了 `P3` 依赖的**全序**

行 372：`P3  evidence(f(...)) = weakest( {evidence(xᵢ)} ∪ {evidence(f)} )`。

`weakest` 需要全序。行 269 给的是 `calibrated < vendor_documented < reconstructed` 这一条链**外加**一个 `not_applicable`——**它在链上的位置未定义**，而 `⊥`（行 241）在链上的位置同样未定义。三种补全全坏：

- `not_applicable` 最弱 ⇒ 任何一个 `exact` 输入把全链拉成 `not_applicable`；
- `not_applicable` 最强 ⇒ 它在任何复合量上被吸收 ⇒ 与 C1 合流，仍然只出现在叶子上、仍然不解决守恒；
- 不可比 ⇒ `P3` 是偏函数 ⇒ **证据传播在含 `exact` 输入的每一处都无定义**，而那是绝大多数节点。

行 373-375 已经为 `weakest` 打过一次补丁（"只在同一物理量的证据链上取"），说明这条律本来就脆。**加值域必须同时给序**，这一格 §11.4 查不到（它只查"值域恰为四值"，查不到序）。

## C3 · `θ_res` 恒触发 ⇒ **头号输出恒 `undetermined`**；而 r6 给的最小修补在 F2 之后**不再够**

行 1767：`∨ Σ own_residual_width / peak.lo > θ_res`。

r6 R4 指出分子无求和域，最小修补是限到 `i ∈ live(t*)` 使它成为占比。**F2 之后这条修补不够了**：

- 分子：来源④ 对存在性型 `replication` 给出的宽度**等于该量自身**（`[0, X]` ⇒ `width = X`）。限到 `live(t*)` 之后，分子 ≈ 主副本 + 优化器状态 + 梯度桶 + 通信 buffer ≈ **16–20 B/param 量级**；
- 分母：`peak.lo = inf_interleave(size := size.lo)`，而这些量的 `size.lo = 0` ⇒ 分母 ≈ 参数本体（bf16 ⇒ **2 B/param**）+ 峰值时刻的激活。

⇒ 比值**结构性地 ≈ 9 或更高**，与并行配置无关。⇒ 对任何 `θ_res < 9` 恒触发 ⇒ `VERDICT-WITHDRAW` 恒发生 ⇒ `oom_verdict` 恒 `undetermined` ⇒ **`G-M2a` 与 `G-M2b` 同时恒红**。

**且它不是占比**：`own_residual_width` 与 `size.lo` 量纲相同但**取自不同端点**，比值没有 1 的上界——把它写成"占比"（行 1768 的注释）是错的。

**最小修补**：按行 1788 自己的原则**删掉这条阈值**，改为首页强制打印 `own_residual_width` 的 top-N。L-032 要解的病（"`G-B1a` 的残差没有下游后果"）在 `peak.hi` 可计算之后**自动消解**——残差宽度已经并进 `peak.hi` 了，那就是后果。

## S1 · 【靶子一】L-008 的 alias 下传使**全部字节**落 P5 兜底 ⇒ `peak` 两端同时不可算 ⇒ `G-M2` 恒红

**这是本轮修复自己挖的最深的洞，且它就藏在"刚修好的地方"。**

正文行 1383（本轮新增的 inv 框，L-008 的落点）：

> alias 判定按 P4 必须污染**每个 storage 的字节**⋯⋯所以**每个 `size` 都背 `replication(alias_rules)`**，不是只有下界构造背。

**构造**：
1. 由该句，任意 storage 的 `size` 其 `roots ∋ replication(alias_rules)`，且按 P4 该根来自 alias 等价类的判定机制——一个复刻规则 ⇒ 由 P2 该机制是 `MechanismOp`，`self_certainty = modeled`、`own_evidence.grade ∈ {reconstructed, calibrated}`（行 339-341）。
2. alias 规则**没有标定点**（§5.1 honest 框、§14.3 第 2 条：alias 判断"完全无验证手段"）⇒ `grade = reconstructed` ⇒ **P5 来源③ 不适用**。
3. alias 不是被抽象模块 ⇒ 来源① 不适用；不是反向双候选 ⇒ ② 不适用；`replication` 不在来源④ 的适用域 `roots ∩ {abstraction, declared_semantics, assumption} ≠ ∅` 内（行 358-360，**这正是 L-009 的修复钉死的**）⇒ ④ 不适用；alias 不是"由复刻规则 + G4 事件序组合算出的组合上界"，它决定的是求和的**值域**本身 ⇒ ⑤ 不适用。
4. ⇒ **五个来源全不适用 ⇒ 每个 `size` 落 P5 兜底 ⇒ `size.hi` 一律"不可计算"。**

**后果**（三条同时成立，任一条单独就足以否掉本轮的核心声明）：

- `peak_reserved.hi` 不可计算 —— 且**与配置无关、与标定进度无关**：§10.2b 的合取条件 `S_∞ ∩ live(t*) = ∅` 在结构上**永不成立**（`live(t*)` 非空 ⇒ 其中每个成员的 size 都在 `S_∞` 里）⇒ **`oom_verdict = false`（装得下）在任何配置下不可达**。
- `G-M2` 的洁净配置 fixture（"全部算子 Tier 1、无手写 placement、无 `assumed` 负载、无 `user_override`、碎片模型已标定"，行 1488-1490）**不排除 alias**——洁净度的五个条件没有一条碰得到 alias 规则 ⇒ **洁净配置也逃不出 `S_∞` ⇒ `G-M2` 恒红**。
- §10.2b 的 `S_∞` 十一行清单（行 1458-1469）在这条修复之后**是错的**：它把 `S_∞` 列成十一个可枚举成员并据此排"标定路线图"，而实际上 `S_∞ ⊇ live(t*)` 的全部字节。首页强制打印的"`S_∞ ∩ live(t*)` 的完整成员清单"（§10.5）随之退化为"把 `live(t*)` 抄一遍"。

**与裁定 #9 的直接冲突**：裁定 #9 的理由是"合并后求和仍精确 ⇒ **不吃 `own_residual`** ⇒ 不落兜底 ⇒ `true` 恢复可达"。而正文行 1383 已经把 alias 根装到了每个 `size` 上——**两者不能同时为真**：要么 alias 判定不进 provenance（则 L-008 未修），要么它进（则裁定 #9 的"不吃残差"为假）。裁决者在裁 #9 时用的是 L-054 的旧口径，没有把 L-008 的落地文本代进去。

**最小修补**（一条，同时解 S1 与裁定 #9）：给 `alias_rules` 一个**来源④ 形态的界**，并把来源④ 的适用域从 `{abstraction, declared_semantics, assumption}` 扩到"任何**对世界的断言型**复刻规则"：

```
lo 端 = 声明成立时的求和（按我们的等价类，最粗划分）
hi 端 = 声明完全不成立时的求和（每个 TensorId 各占一块，最细划分）
```

两端**都由定义式算出**，正是来源④ 的标准形态；且 hi 端恰好等于"alias 全判错"的和 ⇒ 它是真的界。副产物：这个 hi 端就是 S7 需要的 `sup_interleave` 的正确划分（见下）。

## S2 · 【靶子一】P5 兜底的"已知下确界"**没有生产者**——二选一被换成了一个连续自由度

正文行 368-372 与 411-413：

> **保留能被算出的那一端，放弃算不出的那一端**⋯⋯能算出的是**下确界** ⇒ `direction := lower`，`interval := [已知下确界, 不可计算]`。这条规则**不看该量落在算式的哪一侧**，因而不会因减法翻方向而自相矛盾。

**它确实解掉了 L-001 的方向问题**（`C_eff.hi = HBM − 减项.lo` 可算 ✓，`true` 侧恢复）。**但它引入的新洞比原洞更隐蔽**：全文没有任何一处规定"已知下确界"这个数**由谁产出**。

正文只在一处实例化过这个概念，行 421：

> 减项的下确界是 **0**（非负）⇒ `C_eff.hi = HBM` 可算。

**构造 A（按正文自己的唯一实例化，一致地读作"可证的下确界"）**：对每个兜底量取其可证下界 0。fp32 主副本的 `modeled` 来源正是"框架**是否真的建了这块**"（行 402-404 原文）⇒ 可证下界是 0，不是 `4×numel`；梯度桶、重算副本、通信 buffer、workspace 同理 ⇒

```
peak_allocated.lo = Σ (certainty = exact 且不落兜底的 size.lo) ≈ Σ 参数本体字节
```

而 `C_eff.hi = HBM_total − 0 − 池划分.lo ≈ HBM_total`。⇒ `true`（会 OOM）要求 `Σ 参数本体 > HBM_total` —— 在**任何做了分片的训练配置**上为假。叠加 S1（`false` 结构性不可达）⇒ **`oom_verdict ≡ undetermined`，`G-M2` 恒红。L-001 没有被修好，只是从"两值在类型上同时不可达"变成"两值在实践上同时不可达"。**

**构造 B（读作"我们算出的那个值"）**：`peak.lo` = 我们对每一项的点估计之和。于是显存链上**唯一可达的确定结论**（`true`）由一个**不承担任何可证伪义务、没有宽度、没有证据等级约束的点估计**单独决定。而 §10.2 行 1408 自称 `peak_allocated.lo` 是"显存链上**唯一**能产生可被真机 OOM 事实证伪的断言的构件"——**唯一的可证伪断言建在一个无生产者的数上**。这正是 D15/§2.1 要杀的"伪装成区间的点估计"，被从区间宽度赶到了下界端点上。

**两个实现者可以给出相差数十 GB 的 `peak.lo` 而没有任何门能判**——正文自己对旧选侧规则说过这句话（行 410）："结构性复活检测抓不到它：它不是字段、不是枚举值、不是转换算子。" 新规则原样继承了这个性质。

**最小修补**：兜底量必填 `inf_witness : Expr`，schema 断言 `roots(inf_witness) ⊆ {source, configured, transcribed}` 且 `certainty(inf_witness) = exact`；无法给出者 ⇒ `interval.lo` 也标"不可计算"（此时 `peak_interval` 两端皆不可算，方案自曝，这是诚实的）。`inf_witness` 进 digest、进首页 `S_∞` 清单的一列。零新类型。

## S4 · 【靶子一】`exact` 的开放判据用 `block_code = null` 冒充"出厂内置" ⇒ §2.1 的病原样复活，且 `L-mono` 硬失败

§6.4（行 993-997）与 P2（行 336-338）把"出厂内置"这件事**机器化**为 `origin.block_code = null`，并称"两者的区别机器可判且**不可伪造**"。

**它不是"出厂内置"的判据。** §6.2 的三个注册域里，**User 域**的定位是"补 native 未覆盖的算子"、加载自**用户目录**。一条**主动写**的 User 条目（不是由某次阻断触发生成骨架）**没有阻断码** ⇒ `block_code = null`。

**构造**（每一步都合法）：
1. 用户在 User 域主动写一条 `FlashAttentionV3`，`atomic_scope` 单算子；
2. `origin: { block_code: null, site: builtin, readability: FULL }`；
3. `epistemics: { self_certainty: exact }`。

**每一道门都绿**：
- §6.7 步骤 4 的值域裁剪：三条限定全满足 ✓（`exact` 无需 `CalibKey`）；
- §11.4 的复活检测：断言 `exact` 条目满足 `block_code = null ∧ readability = FULL ∧ 单算子`，全满足 ✓；
- `native_exact_ledger` 只是**打印**，不阻断；
- §2.4 的分派表**只作用于 `block_code ≠ null` 的条目**（行 302-304，这是本轮新加的限定）⇒ 该条目**不背 `abstraction` / `declared_semantics` 根**。

**后果（每一个指标都变好）**：其 shape / dtype / storage 面 `exact` ⇒ 区间为点 ⇒ 不落兜底；不进 `θ_abs` 分子；不进 `U` 的子句①；`c1`（`exact` 字节占比）**上升**；`c4` 不变；`c2`/`c5` 不变 ⇒ **`clean` 向量逐分量不降、至少一个严格上升 ⇒ `L-mono` 被直接违反**。

而 `G-B0` **管不到**：它的射程是"补救模板"（行 1661-1664），而这条注册**不补救任何 `BLK-*`**——`block_code = null` 就是它不补救任何阻断的证明。这正是 L-029（档 2）说的射程问题，**被本轮的 `exact` 开放从理论风险变成了一条具体的、可照抄的操作序列**（见 §3 升档）。

**第二处**：`readability` 被反复声明为"PE 在**阻断时刻**计算并写入，**用户不可填**"（§2.4 行 287、§11.2 步骤 2 行 1638）。**对 `block_code = null` 的条目不存在"阻断时刻"** ⇒ 该字段**没有生产者** ⇒ 它在 YAML 里是手写的（§6.3 的 `Reshape` 示例就是手写 `readability: FULL`）。⇒ **"唯一不可能被声明伪造的候选是 AST 在不在"这条论证（行 296-297），恰好在它唯一被用来把关的那一类条目上失效。**

**最小修补**：`exact` 的第一条限定从 `block_code = null` 改为 **`注册域 = Native ∧ 条目 digest ∈ 工具发布产物`**——§6.2 已经把三域物理隔离、Native 域"只读"，这是一条**用户在类型上碰不到**的现成判据；`readability` 对 Native 条目由**工具构建期**的 PE 一次性算出并进发布 digest；User / NativePatch 域一律 `self_certainty ∈ {modeled, assumed}`。零新构件。

**第三处（同一格的次生问题）**：§6.3 唯一的完整示例给 `Reshape` 写的是 `self_certainty: modeled` + `evidence.grade: reconstructed`（行 939），而 §6.4 用整整一个 bad 框论证**正是这一类**必须能拿 `exact`。§6.3 自己说过"**示例错了比正文错了更危险——读者会照着实现**"（行 946）。照着实现 ⇒ `native_exact_ledger` 为空 ⇒ §6.4 的修复在实现上等于没做 ⇒ 见 S9。

## S5 · 【靶子一】P4 表把 `abstraction(atom_substitution)` 装在主数据通路上 ⇒ `θ_abs` 是第二道 `θ_evd`（恒触发）

L-014 的修复（P4 必填表，行 452-461）给 `Pass_impl_select` 钉死 `own_roots = abstraction(atom_substitution)`。

**构造**：任何选了实现族的配置（融合 attention / grouped GEMM / fp8——§13.1 的基准配置三项全开）⇒ `Pass_impl_select` 产出替身节点，其输出 shape 带 `abstraction` 根 ⇒ 由 P1（`roots(f(x)) = ∪roots(xᵢ) ∪ own_roots(f)`）与 P8（只升不降），该根沿残差流**传播到该点之后的每一个激活字节**——transformer 的残差流使"该点之后"= 第 0 层之后的全部。⇒

```
judged / base  =  Σ_{带 abstraction 或 declared_semantics 根} size.lo  /  Σ size.lo  →  ~1
```

⇒ 对任何 `θ_abs < 1` **恒触发** ⇒ `VERDICT-WITHDRAW` 恒发生 ⇒ `oom_verdict` 恒 `undetermined`。

**这与 §10.4 自己删掉 `θ_evd` 的理由逐字同构**（行 1567-1577）：「恒红的门与恒绿的一样坏——它不携带信息，且会把 `VERDICT-WITHDRAW` 变成常态，使真正的触发原因被淹没。」`θ_evd` 是通过 `evidence.grade` 饱和恒红的；`θ_abs` 现在通过 `roots` 饱和恒红。**同一个病，换了一条轴。**

更讽刺的是 §6.6（行 1020）把这个行为当作设计优点写进不变量：「若白名单被放宽，`abstraction_covered_bytes` 随之暴涨、Θ 门自动触发——放宽的代价自动出现在答案形状里」。**现在它不需要放宽白名单就暴涨了**，只需要用一个融合 kernel。

**正文自己给了修补，只是没用在门上**：行 1562 已经定义了 `own_coverage(r) := Σ_{i : r ∈ own_roots(producer(size_i))} size_i`（"只算这个根是在哪个节点上产生的，不算它传播到哪"），但只把它放进 ledger 与首页第二列，**门的分子仍用饱和的 `roots`**。L-004 的建议修法原文是"Θ 门分子改用 `own_coverage` 的并"——**正文只落了一半**。

**最小修补**：`judged := Σ_{i : {abstraction, declared_semantics} ∩ own_roots(producer(size_i)) ≠ ∅} size_i.value`；`base := Σ_i size_i.value`。两处改动：`roots → own_roots(producer)`（消灭饱和）、`.lo → .value`（消灭 S13 的失明）。`value` 是 `Q[T]` 的现成字段（行 223），恒存在、恒可算、且 §11.4 禁的是**峰值与 step time** 的标量形态，不禁把 `value` 用在一个覆盖率分母上。

## S7 · 【靶子一】`max / min over 四角` 不是包络，是抽样；`.hi` 侧因此不是界，`.lo` 侧的时刻轴恒无效

§10.2 的合成式（L-002 的落点）：
```
peak_allocated.lo := min over 四角 : inf_interleave(size := size.lo)
peak_allocated.hi := max over 四角 : sup_interleave(size := size.hi)
```

**(a) `.hi` 侧不是界。** 四角是"(字节端点 × 时长端点)"。而 §13.3 档 C 把 `timing_dependent` 通信时长与 allocator 碎片/保留明列为**非单调**维度，并用 **Graham 异常**做依据。非单调函数在盒子上的最大值**不必在角点取到**。

> **构造**：两块通信 buffer A、B，各自的 `Free` 时刻是同一条通信边时长 `d` 的函数（`timing_dependent`）。`d = d.lo` 时 A 已释放而 B 尚未分配；`d = d.hi` 时 B 已被推迟到 A 之后；只有 `d` 落在区间**内点**时两者的生存区间重叠。⇒ 真峰值在内点取到，四角求值**全部漏掉它** ⇒ `peak_allocated.hi` 低于真值 ⇒ **可以假证"装得下"**。

这是本方案唯一一个"低估 `peak.hi`"的通道，而 §10.2 的两个 honest 框只讨论了 alias 导致的**高估**（假 OOM），没有一处讨论低估。

**(b) `.lo` 侧的时刻轴恒无效。** `inf_interleave := max over 节点 n ∈ **G4 偏序** : Σ_{def(s) ⪯ n ⪯ lastuse(s)} size_s`，且**条件二**已把"`lastuse` 由 `timing_dependent` 边决定"的 storage **全部排除**（行 1389-1391）。⇒ 剩下的 `⪯` 是**纯结构偏序**，与任何时长取值无关 ⇒ **时长端点对 `inf_interleave` 没有自变量** ⇒ `min over 四角` = `min over 2 个字节角`；又因 `inf_interleave` 对 `size` 逐项单调递增 ⇒ 最小值在 `size.lo` 角 ⇒ **四角在 `.lo` 侧是纯浪费**。

**(a)+(b) 合起来给出一条比裁定 #8 更好的走法**：四角**只作用于 `.hi` 侧与归因**，`.lo` 侧钉死为 2 角。这**直接消掉 L-024 的遍数冲突**（`.lo` 侧不再要 4 次 liveness），且**不引入任何门控常量**（裁定 #8 引入了一个"TD 字节占比 > 工具常量"的阈值，见 §2 裁定 #8）。而 `.hi` 侧的正确修补不是加角，是**换构造**：`sup_interleave := Σ_streams peak_s` 里的 `peak_s` 本就应当是"对该流上**全部 t** 取 max"，把时长区间的影响并进 `size` 侧的保守放大（每条 `timing_dependent` 边把受影响 storage 的存活区间取**并**），得到一个真正的结构性上界，不再需要时长角。

## S11 · 【靶子一】L-006 的 `G-B4` 双端修复，架空了 `direction` 的单侧语义（三处）

L-006 的落点（§2.8 行 552）：

| 出处 | 原文 |
|---|---|
| §2.3 行 269-271（删 `nominal` 的**全部**理由） | 「**它使区间塌成点**⋯⋯`certainty = assumed ⇒ direction ∈ {upper, lower}`，**必然单侧开口**」 |

## S14 · 【靶子一】成员资格 `[0, size]`：既无触发判据，又不满足它自己声称的"两端都可算"

## S18 · 【靶子一】来源⑤ 的界只覆盖**内部**碎片，且与 §14.3 的能力边界条目直接冲突

来源⑤（行 365-367）：「碎片 ≤ **活跃分配块数 × 最大对齐/分块粒度**」，并称"不依赖任何扫描、任何标定点，是纯组合量 ⇒ **是界，不是样本**"。

**(a) 它是内部碎片的界，不是碎片的界。** `n × granularity` 界住的是"每次分配向上取整的余量之和"。缓存型显存 allocator 的主要损失是**外部碎片**：空闲块的尺寸分布与请求尺寸不匹配（一块 100 MB 的空闲块喂不了 101 MB 的请求）。外部碎片的上界与"活跃块数 × 粒度"无函数关系——它取决于**空洞的分布**，最坏可达池容量本身。⇒ 该式**不是保留峰值的上界**，把它当上界用 ⇒ `peak_reserved.hi` 偏低 ⇒ 与 S7(a) 同向，**可假证"装得下"**。

**(b) 两处规定不能同时为真。**

| 出处 | 原文 |
|---|---|
| §10.2b 行 1469 | 碎片 · allocator 池划分 —— 二者都有**结构性上界** ⇒ **不落兜底、不进 `S_∞`** |
| §14.3 行 2075 | **在 allocator 碎片模型标定之前，"装得下"这个结论在原理上给不出来**（§10.2b）——**这不是精度问题，是可判定性问题** |
| `G-M2` 行 1489 | 洁净配置要求「**碎片模型已标定**」 |

来源⑤ 若成立，§14.3 那条能力边界与 `G-M2` 洁净配置的第五个条件**都是残留**；来源⑤ 若不成立（按 (a)），则 `C_eff` 失去 `Q` 形态、`G-X7` 红、§2.10 的失效原样回来。**必须显式选一条。**

**(c) 输入量自身的 provenance 未定。** "活跃分配块数"由 `live(t*)` 的成员资格给出——而由 S14，成员资格本身可能不确定 ⇒ 块数是区间 ⇒ 界的 hi 端要用块数的 hi 端；"最大对齐/分块粒度"是 allocator 复刻规则的常数，`replication + reconstructed` ⇒ 它自己**落兜底** ⇒ 其 `.hi` 不可计算 ⇒ **来源⑤ 算出的"界"的上端不可计算**。正文未指出这一条。

**最小修补**：把来源⑤ 的适用面限定为**内部碎片**并改名 `alignment_overhead`；外部碎片明确留在 `S_∞`，同时接受"`false` 在碎片标定前不可达"（这就是 §14.3 原本的诚实结论）；`C_eff` 的 `池划分` 改走 S8 的 `pool_carve_out`（它是**静态**池切分，确实与事件序无关，来源⑤ 对它成立）。

## S19 · 【靶子一】§12.3 的三个切分算术错，且把外部 oracle 的门记成"我们自己写的对照物"

行 1856-1861：

> 其余 **42** 道里，**17** 道用**我们自己写的对照物**（源码文本、图自身、快照）检模型事实，**27** 道是自律门⋯⋯**显存链的 39 道门全部是自洽性检查**。

- 17 里含 `G-T1` `G-T2` `G-N2`，它们的 oracle 是**真机 trace**，不是"我们自己写的对照物"。

# 2. 十条裁定里站不住的

## 裁定 #2（`G-T1` 方向不对称不改）—— **推翻**

**理由①"改了会让任何未建模 op 硬失败"是稻草人。** R3-1 N1 的原文（台账 L-052）不是"任何未建模 op 硬失败"，而是**正表限定**：「该 op 若属**集合通信族或已注册 op 族** ⇒ 硬失败；只有属于明确声明不建模的族（`TransData` / `Cast` / 内存搬运）才计数」。裁决者列举的三个反例**恰好全在限定之外**——它们从不绑定到任何源码级调用，按 §4.4 步骤 4 也不进 S1 注册域。⇒ **理由① 对被裁的那条修法不成立。**

**理由②"`G-N2` 会塌进 `G-T1`"成立，但它论证的是错的东西。** 是的，N1 版的 `G-T1` 会吸收 `G-N2`（欠预测的 2 个归约 op 属集合通信族 ⇒ 硬失败）。但"塌进"损失的是**独立门的计数**，不是**检出能力**——两道门红一道门红，抓到的缺陷完全相同。裁决者用"我们的门数会从 40 掉到 39、真机 oracle 从 5 掉到 4"来拒绝"唯一的外部裁判在危险方向上永远是软的"这个一等缺陷。**这正是 §12.3 自己命名的那种虚假安全感**（行 1841："'44 道门'这个数本身就是 `G-M1` 要消灭的那种虚假安全感的最高形态"）。**用门数守恒否决检出能力提升，是把计数规则当成了设计规则。**

**理由③（"更好的走法：族内计数门"）自我否定。** 裁决者提议"对每个**已建模的 op 族**断言预测计数 == 真机计数"，并说它"既保住 `G-T1` 的软方向，又把 `G-N2` **一般化**"。**一般化就是吸收**——`G-N2`（桶数 = 归约 op 数）是该新门在"归约族"上的实例 ⇒ `G-N2` 照样塌进新门。裁决者拒绝 A 的唯一实质理由，对它自己的替代方案**同样成立**。

**残余风险的严重度被低估**：全部逃逸构造（漏插通信、桶数欠预测、重算区通信未重执行、精度 cast 缺失）产生的都是**欠建模**；而 §12.3 已经承认"整个方案对'模型算得对不对'的外部裁判只有 2 道相互独立的门，且只看 op 序列"。**这 2 道在危险方向上是软的**，意味着外部裁判的有效道数在危险方向上是 **1**（`G-N2` 的等式）。

**最小修补**：采纳 N1 的正表限定，接受 `G-N2` 塌进 `G-T1`，并在 §12.3 把"数门的正确判据"那段的例证换成一个**不依赖 `G-T1` 软方向**的例子（现成的：`G-C1`③ 与 `G-N6` 共 red fixture 但检出机制不同——档 3 的 L-069 已给出）。

## 裁定 #9（alias 取合并）—— **推翻**

**(a) 与已落地的 L-008 直接冲突**：见 S1。理由中的"不吃 `own_residual`"在正文行 1383 面前不成立。

**(b) 合并只在 `.lo` 侧安全，裁定没有论证 `.hi` 侧。** 理由原文只写"合并只会降低求和 ⇒ 在 alias 规则的**任何**错误下仍是**下界**"。而 §10.2 的合成式对**两端**用同一个 `StorageId` 值域：`sup_interleave := Σ_streams peak_s`，`s` 的取值范围同样是 alias 等价类。

> **构造**：把两个实际独立的 storage 合并进同一 `StorageId` ⇒ `sup_interleave` 少计一块 ⇒ `peak_allocated.hi` **偏低** ⇒ 可假证"装得下"。

**(c) 合并与来源⑤ 相乘，判据 5 反向失败。** 合并降低"活跃分配块数" ⇒ 由来源⑤ `碎片.hi` 下降 ⇒ `peak_reserved.hi` 下降 ⇒ "装得下"更容易。而触发合并的条件是"产出它的算子 **storage 面证据不足**"——**少写 S1 的 storage 面就能触发更多合并**。⇒ 省事 ⇒ 块数少 ⇒ 碎片界小 ⇒ 上界低 ⇒ 答案形状变好，且按裁定的说法**不吃残差**。**判据 5（硬）失败。**

**最小修补（与 S1 同一条）**：两端用**相反的划分**——`.lo` 用最粗划分（合并，保下界），`.hi` 用最细划分（每个 `TensorId` 各计一次，保上界）；两者的差额就是 `alias_rules` 的来源④ 区间宽度，**它必须被记进 `own_residual`**，`|合并集|` 上首页。这同时消掉 (a)(b)(c)。

## 裁定 #7（allocator 维持 `declared_semantics`，Θ 分子不承担）—— **概念上站得住，数值上是空的**

二分本身（`θ_abs` 管人工判断 / `size_unverifiable` 管无残差来源）在概念上正确，且与 §2.3 对 `declared_semantics`（无 AST 对象）与 `replication`（框架行为复刻）的划分一致。**攻不动这一半。**

## 裁定 #4（`CalibrationSet`：张成性 + 留一交叉验证）—— **未堵住 L-028 的构造**

**构造**：域片 `d` 有一个自由维 `seq`。放两个点：`seq = 4096` 与 `seq = 4097`（**互异 ✓，张成性满足**），量写成常数 `c`。留一交叉验证：留下 4097，用 4096 拟合常数 `c₁`，预测 4097 得残差 `|c₁ − c₂| / c₂ ≈ 0`（两点几乎同参数 ⇒ 实测值几乎相同）⇒ `residual_rel ≈ 0` ⇒ 退出兜底、区间塌成点 ⇒ **拿到"装得下"**。

⇒ 裁定只把退化填法的成本从"1 个点"抬到"2 个点"。**"张成性"这个词缺的是"张成多大"，而补上"多大"就是一个阈值**——而 Θ 是闭集、§11.5 禁使用者可设的门限，所以补阈值这条路被自己封死了。

**最小修补（零阈值）**：**域片不是声明的，是导出的**——`域片 := 该量的标定点集在参数空间中的凸包`。两个几乎相同的点给出的凸包几乎是一个点 ⇒ 目标配置必然**越域** ⇒ 按 §11.1 阻断。这与正文对 `sweep_dims` 用过的招（枚举式 → 类型级导出）是同一招，且 `G-X3` 的"域片内标定点集非空"变成同义反复因而可以删掉一条断言。

# 5. 三个靶子之外的新发现

1. **S3（`bucket_order: declared` ⇒ `G-X1` 恒红）** —— 已列在第 1 节，因为它是全篇最便宜也最致命的一条（加载期恒阻断），且它同时命中 §11.4 形态黑名单、§6.4 组合子禁令与 §8.2 自己的 bad 框。三处立论 + 一处 schema。

2. **`G-M1` 的三分类不穷尽，缺"输入校验"一类。** §12.1 定义：门 = 存在至少一个**规格级**缺陷会让它失败；后置条件 = pass 定义的直接推论；报告项 = 必填输出不作判定。但门表里有一整族条目，其 red fixture 是**一份坏的用户输入**，既不是规格级缺陷也不是 pass 的推论：`G-P3`（用户写错 π₀ 绑定）、`G-N1`（spec 取值超框架支持集）、`G-X3` 的 `CalibKey` 解析半边、`G-P2`（用户声明 Tier 1 却指不出捕获点）、`G-B4`（用户把 MoE 负载写成均匀数）。**"规格级"这个词在正文里是二义的**——既可读作"缺陷在规格层（对 实现 bug）"，也可读作"缺陷在用户提供的 `*Spec` 里"。这个二义**是承重的**：它决定 48 个条目里哪些留在"44 道门"。按第一种读法，上列 5 条应被移出验证力度统计（44 → 39，且首页三切分全变）。**最小修补**：`G-M1` 增第四类"**输入校验**"，其 fixture 是坏输入、**不计入任何"我们有 N 道门"的陈述**——这与 §12.3 自己的立论（"把自律门和外部裁判并进同一个数里就是在制造安全感"）完全同向。

3. **`clean` 五分量里有一个 Bool（`c3`），而 `L-mono` 要求"逐分量偏序 ⊑ 且至少一个严格下降"。** `c3 = (oom_verdict ≠ undetermined)` 只有两个取值 ⇒ 一旦它已经是 `false`（在 S1/S2 之下**恒为 false**），它**永远不能再下降** ⇒ `L-mono` 的"至少一个严格下降"只能由 `c1/c2/c4/c5` 承担；而由 S9 `c5 ≡ 0`（L-038）、由 S1 `c1` 只剩参数本体那一小块。⇒ **`L-mono` 的可承担分量实际只剩 `c2` 与 `c4`**，与 L-038 的结论一致，但成因更深：不是 `c5` 一条的问题，而是**恒 `undetermined` 使 `c3` 退化为常量**。这条应与 L-038 合并处理。

4. **`G-R4`（扫描升级）在 `peak.hi` 不可计算时无定义。** 其触发式是"残余维度联合扰动使**峰值区间与容量区间产生新的相交**"。由 S1，`peak.hi` 不可计算 ⇒ "峰值区间"是 `[lo, 不可计算]` ⇒ "相交"这个谓词在其上没有定义。⇒ `G-R4` 要么恒不触发（等于删掉），要么消费者按 §2.7 硬规定① 阻断。台账 §3.3 曾把 R3-3 §2.2 对 `G-R4` 的攻击判为"已消解"，**消解的理由（触发式改写）没有覆盖端点不可计算的情形**。

5. **`RepeatRegion.count : Q[Int]` 与 `G-E6` 的循环。** `G-E6` 断言"随层数、微批数变化的结构关系必须由模型**导出**而非写入公式"，而导出的载体是 `RepeatRegion.count`；`count` 自身的五元组（roots / certainty / interval）全文未定（台账 L-073 已点名，判档 3）。若 `count` 是区间（例如层数经某个 `modeled` 折叠规则得出），则 `× num_layers` 这类关系的**每一处**都继承该区间 ⇒ 全图字节的宽度被一个未定量支配。这条我**没能构造出反例**（`count` 更可能是 `configured/exact`），标为**疑点**。

6. **首页强制字段自身无 provenance（L-056，档 3）在 §10.4 改口径后性质变了。** §10.4 现在**不再**消费 `abstraction_covered_bytes` / `declared_semantics_covered_bytes`（它自己算 `judged`/`base`），⇒ L-056 的"拿前两个去与 Θ 比较"这条指控已不成立，但**新的**问题是：首页那两个字段与门里的 `judged` **是两个不同的数**（一个是和、可 > peak；一个是并、∈[0,1]），而报表没有说明它们不同。读者会拿首页的比例去核对门有没有触发，核不上。**最小修补**：首页并印 `judged / base` 这个**门实际用的**比值，并标注它与八行覆盖表的口径差异。

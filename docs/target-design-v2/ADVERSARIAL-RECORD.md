# 对抗记录（设计文档的旁路档案）

> 设计文档 `index.html` 只讲**方案本身**。这份档案留住它是怎么被打出来的——
> 哪些做法被试过并否掉、哪些论证塌过、哪些结论被推翻过。
>
> **它不是设计文档的一部分**，实施时以 `index.html` 为准。这里只回答一类问题：
> 「这条为什么是现在这样，而不是那个更自然的写法？」

**纪律**：全过程**未读现有实现代码**，也未执行任何代码。理由——委托方在做重构，
现有实现与目标形态可能差异极大，读它会污染对新方案本身的评判。

---

## 一、过程

四轮对抗，每轮「提案 → 反驳 → 仲裁」。

| 轮 | 做了什么 | 主要产出 |
|---|---|---|
| 1 | 红队 48 问 + 六判据 + 五种作弊手法；反驳给出 8 个反例 | 确立**零逃逸六判据**，判据 5（代价单调性）定为硬要求 |
| 2 | 按反例重写提案 | PE / π₀ / provenance 代数的雏形 |
| 3 | **四流并行修复**（policy-free 支点 / provenance 代数 / 门体系 / 规模与缺输入）+ 仲裁裁定书 | 层序改动、`readability`、`G-B1a`、门编号重编、能力边界 E |
| 4 | 攻第三轮新引入的面 + 审四条未检验候选 + 五元组一致性 | P5 兜底改单侧、`G-M2`、§10.2b 不对称、推翻 `G-N2` 的降级 |

三条外部裁定的硬前提贯穿全程（正文 §0.1）：真机对照仅限 op 级 time 记录（**P-oracle**）；
端到端峰值标量同样排除（**P-peak**）；不接受任何人工例外条款（**P-noexc**）。

## 二、被推翻过的结论（按严重度）

### 2.1 「无机器残差 ⇒ 保持点值」——两个独立反驳者同时撞到

**曾经的写法**：`evidence.grade ∈ {vendor_documented, reconstructed}` 时 `own_residual`
无机器来源 ⇒ **不伪造一个数** ⇒ 该量的 interval 保持点值。

**为什么错**：不可验证的那部分字节（allocator 行为、融合 workspace、通信复刻、分桶规则）
对区间宽度的贡献**恰好为零**。于是"峰值只有区间形态"这条不变量被架空——
输出是一个**伪装成区间的点估计**，而它最容易错的方向（低估）正是用户最想采信的方向。

**现在**：兜底改「取单侧」（正文 §2.5 P5、决策 D15）。代价是标定不足时说不出"装得下"——
这是有意的，`CalibrationSet` 由此成为真正的交付物。

### 2.2 `PolicyStateBinding` 的「被写过」是语法判定

**曾经的写法**：读取任何 import 后**被写过**的模块级可变全局，若不在声明表里 ⇒ 阻断。

**反例**：

```python
_STATE = {'tp': 1}                      # 模块级绑定一次
def init(...): _STATE['tp'] = world_size   # 只改字典内容，绑定从未被重写
```

"被写过"为假 ⇒ 不阻断 ⇒ PE 把 `tp` 读成 1，provenance 是 `source/exact`。
**策略污点从未生成，policy-free 断言平凡通过，而答案是错的**，且每个指标都变好。

**现在**：判据画在**读**的一侧（正文 §3.4）。

### 2.3 `G-N2` 被误判为 `G-T1` 的「特例投影」

曾按「共用同一条 trace」把桶数对照门降级、不独立计数。**反例**：分桶欠预测（我们 4、真机 6）时，
我们的序列**仍是**真机序列的合法保序子序列 ⇒ `G-T1` 绿；而计数不等 ⇒ `G-N2` 红。

**教训已写进正文 §12.3**：子序列断言非对称（只惩罚"多"），等式断言严格更强。
数门的判据是「能否构造缺陷使 A 红而 B 绿」，不是「它们读同一份数据吗」。

### 2.4 门数算错

曾写「31 条目 / 真门 26」，而按 oracle 分布之和是 31——自相矛盾。
重数：**44 条目、后置条件 3、报告项 1 ⇒ 真门 40**，其中只有 5 道拿真机数据当裁判。
连带修掉「§7.3 叫后置条件、门表里标门」的分类冲突。

### 2.5 `peak_lower` 的方向搞反过

曾写「不补下界的话，本方案永远只能证明装得下、永远不能断言 OOM」。
把碎片算进来之后**正好倒过来**（正文 §10.2b）：`reserved = allocated + 碎片`，碎片 ≥ 0
⇒ 「会 OOM」可判定（碎片救不回来），「装得下」当且仅当碎片模型有上界。

### 2.6 值域裁剪把方案锁死在自己的门下

**曾经的写法**：`RegisteredOp.self_certainty ∈ {modeled, assumed}`，`exact` 不在值域里。
意图是堵住"注册一条语义就把人的判断变成事实"。

**为什么错**（推理三步，每步都是方案自己的规定）：

1. S1 是算子语义的**唯一**词典 ⇒ 每个张量的 shape/dtype/storage 都由某个 `RegisteredOp` 求值；
2. 一律不许 `exact` ⇒ 由 P2，**全链没有一个字节是 `exact`**；由 P3 取最弱，**evidence 恒为 `reconstructed`**；
3. ⇒ `θ_evd` 与 `θ_abs` 对任何小于 1 的取值恒真 ⇒ `VERDICT-WITHDRAW` 恒触发 ⇒ `oom_verdict` 恒 `undetermined`
   ⇒ **`G-M2` 在方案启动第一天就是红的**。

**病根**：把两类注册项混为一谈。要堵的是"**用一次注册来消化一次阻断**"；
而 `Reshape` 是工具出厂就带的算术事实，它不消化任何阻断。
区别机器可判且不可伪造：**`origin.block_code` 是不是 `null`**。

**现在**：`exact` 仅当 `block_code = null ∧ readability = FULL ∧ 单算子粒度`，
并进 `native_exact_ledger` 参与 digest；§2.4 的 `readability` 分派表也**只作用于
`block_code ≠ null` 的条目**——出厂 native 语义不背 `abstraction`/`declared_semantics` 根。

### 2.7 P5 兜底的"选侧"曾是一个无机器判据的二选一

**曾经的写法**：`direction := 单侧（按该量对峰值的偏置方向定 upper/lower）`。

**为什么不可执行**：① "偏置方向"二义（"我们给的值偏向哪边" vs "它把峰值推向哪边"），
两种读法在碎片上结果相反；② 对绝大多数兜底量真值方向本就不唯一
（fp32 主副本：框架没建 ⇒ 我们是 `upper`；建得更多 ⇒ 我们是 `lower`，两边都能自圆其说）；
③ `C_eff` 的减项不作用于 peak，规则的自变量不存在；碎片与通信时长非单调，"偏置方向"无定义。

**后果**：实现者对每个兜底量握有一个二选一，而它决定头号输出——全选 `upper` 永远说不出"会 OOM"，
全选 `lower` 永远说不出"装得下"。**结构性复活检测抓不到它**（不是字段、不是枚举、不是转换算子）。

**现在**：取**使 `oom_verdict` 更难变确定**的那一侧——peak 的加项取 `lower`、`C_eff` 的减项取 `upper`。
它是唯一一条不需要知道真值方向就能执行的规则。

### 2.8 "碎片标定是决定成败的那一件事"——排他表述是错的

`S_∞`（P5 兜底集）里**任何一个**成员单独就足以使"装得下"不可判，而碎片按字节量级排在
优化器持久项（16 B/param）、梯度桶、重算副本、`free_policy` liveness 差、梯度值之后。
原表述会把**标定路线图排错序**。现改为合取式，并把报表首页那行从"碎片未标定时打印"
改为"`S_∞ ∩ live(t*)` 非空时打印其完整成员清单"。

附带一处自相矛盾：曾写"碎片是 `reconstructed`，按 P5 它有标定点才有来源 ③"
——而来源 ③ 的前置条件正是 `grade = calibrated`。`evidence.grade` 不是固定属性，是**标定进度条**。

### 2.9 其它被修正的一致性问题

| 问题 | 处置 |
|---|---|
| §2.8 曾写「`configured` 是八种根里**唯一允许精确**的那个」 | 又把 `certainty` 写成了 `roots` 的函数（§2.1 的病复发）。改为「唯一一个**其叶子取值本身不承担可证伪义务**的根」 |
| step time 四处说有区间、一处说撤销 | 取"没有区间"。类型层论证：makespan 是 `Sample[Float]`，而不存在 `Sample→Q` 转换算子 ⇒ step time 在类型上不可能是区间 |
| 五个 pass（`train_step`/`precision_opt`/`fusion_dist`/`remat`/`sched`）没有 `own_roots` | P4 在它们上无法执行，而它们恰好合成字节量最大的东西。补成覆盖全部九个 pass 的必填表 |
| `policy(·)` 是闭集外的第九个根名（6 处） | 改为**根上的谓词**：`policy(q) :⟺ ∃p ∈ roots(q): p = configured(f) ∧ class(f) ∈ {Π_extent, Π_impl}`。`Root` 保持八值闭集 |
| `kind` 枚举不够用 | 补 `partial_residual_site`（`PARTIAL` 未求值站点，正文已要求打 `abstraction` 根却无 kind 可填）、`op_identity_mapping`、`psi_projection`、`canon_ruleset`；并给 `declared_semantics` 也加 kind |

### 2.10 头号输出曾在类型上没有生产者

`oom_verdict` 是 `cmp(peak, C_eff)`。而 `C_eff = HBM_total − framework_reserve − 池划分开销`，
其中**池划分开销**属非单调维度 ⇒ 其产物是 top-N 扫描的**样本极值** ⇒ 按代数即 `Sample[Int]`。
而 `Sample` 上**没有 `cmp`**、**不进 OOM 链**。⇒ **比较在类型上不存在。**

连带失效的是：`VERDICT-WITHDRAW`（唯一落点就是 `oom_verdict := undetermined`）、
"用真机 OOM 事实反证 `false`"（该值不存在）、`peak_lower` 的全部用途、`G-M2`。

**为什么四轮都没人发现**：讨论这个判定点的两处（谁输出 `undetermined`、扫描升级与判定的先后）
关心的都是**所有权与顺序**，没有人问"**这个比较在类型上合法吗**"。

**现在**：碎片与池划分各获一个**结构性上界**（P5 来源 ⑤：由复刻规则 + G4 事件序组合算出，
形如「碎片 ≤ 活跃分配块数 × 最大对齐/分块粒度」，不依赖任何扫描与标定）⇒ `C_eff` 恢复为 `Q`。
加 `G-X7` 把它钉成类型断言——这个失效是沿数据流悄悄发生的，只有类型断言能在改动点当场拦住。

### 2.11 `sweep_dims` 的枚举式定义漏掉了字节量最大的两份 spec

曾写 `sweep_dims := {f ∈ Q2表 : class(f) ∈ {Π_extent, Π_impl}} ∪ RematSpec ∪ ScheduleSpec ∪ ImplSpec`。
`DistOptSpec` 与 `PrecisionSpec` 是后加的，**不在这个并集里**——而 `free_policy`（几十 GB）与
`master_weights`（16 B/param，训练态最大持久项）正在其中。更糟的是它们**也不出现在
`excluded_from_sweep`**（该栏只列"因被改判而退出"的字段）⇒ **作为自由度在报表上完全不可见**。

**现在**：改为类型级导出 `{ f : f ∈ 任一 *Spec 的字段, class(f) ∉ {Model, Env} }`，
八份 spec 的每个字段都进分类表。"新增一份 spec 却忘了加进扫描"这类复发在结构上不可能。

### 2.12 门数印得不诚实

曾印"40 道真门，其中 5 道拿真机数据当裁判"。这个数**本身**就是 `G-M1` 要消灭的那种虚假安全感：
5 道里有 2 道（`G-T0`/`G-T0b`）检的是 **oracle 自身的纯净度**（留出、版本），不检任何模型事实；
`G-T2` 与 `G-T1` 共 oracle。**⇒ 对"模型算得对不对"的外部裁判只有 2 道相互独立的门，且只看 op 序列。**

**现在**：报表首页与 §12.3 强制并印三个切分（外部 oracle 5 / 检模型事实 3 / 相互独立 2），
再切一刀"检模型事实 17 : 自律门 24"。**不得只印门的总数。**

### 2.13 `θ_evd` 是一道恒红的门

`(reconstructed + vendor_documented) / peak > θ_evd`：显存链大部分由复刻构成
（allocator、通信插入、分桶、重算克隆、精度主副本），全是 `replication + reconstructed`，
其中重算副本在全层重算下就是**全部激活字节** ⇒ 该比值对任何小于 1 的阈值**恒真**。

**恒红的门与恒绿的一样坏**——不携带信息，且把 `VERDICT-WITHDRAW` 变成常态，
使真正的触发原因（人工判断占比过高）被淹没。

**现在**：删除。"是复刻"是这类仿真器的**常态**，"没有残差来源"才是病，
而后者已由类型层处理（落 P5 兜底 ⇒ 单侧 ⇒ `peak.hi` 不可算 ⇒ `undetermined`），**不需要阈值**。

### 2.14 死掉的论证（结论保留，理由换掉）

| 论证 | 为什么死 | 换成什么 |
|---|---|---|
| 「分层是为了支持交互式 what-if」 | 产品形态确定为"配好配置直接出结果"，无此消费者 | `G-L1`：一层存在 ⟺ 它是某条不变量唯一能被陈述的位置 |
| 「反向必须派生，否则改重算配置会使 CoreIR 缓存失效」 | 同上 | policy-free 是 CoreIR 唯一的断言点，写进去就没地方陈述它了 |
| 「活跃集合在真机 allocator dump 里可观测」 | P-oracle 下为假 | 归因口径改为对**模型**可扰动，并声明它不使显存模型可证伪 |
| 「注册要被四道门打」 | P-oracle 删掉了其中两道 | 两道门；storage/placement 面的注册项没有独立对照物 |
| 「真机对照是唯一正确性判据」 | 对显存侧为假 | 时间链有 oracle；显存链全部改称**自洽性检查** |

## 三、被试过并否掉的做法

### 3.1 四条「第二把尺子」候选

P-oracle + P-peak 之后显存链无外部裁判，于是找过四条替代 oracle。**记在这里免得重新发明**：

| 候选 | 裁定 | 为什么 |
|---|---|---|
| **allocator 停顿显形为 `O` 的同流间隙**（只比对越水位点的序号，不做时长→字节反解） | **降为报告项** | 分配是**主机侧**动作，设备间隙 = 主机停顿 − 排队深度，而**排队深度不在 `O` 里**；且"这个间隙是设备 malloc 还是调度气泡"的判别需要一个新阈值，落进已被消灭的阈值门射程 |
| **op 计数与位置约束 liveness 成员资格** | **采纳一半** | gather / 重算侧成立（有真实设备 op）；**释放侧不成立**——`FreeParam` 是主机侧归还，在 `O` 中不存在 ⇒ `free_policy` 的 `at_step_end` 与 `never` 结构性不可分辨（已进正文 §8.2 与诚实边界） |
| **判别式探针**（主动造 oracle，探针不必是目标模型） | **窄采纳** | 只对 `replication` 根合法（规则是全称量化的，小探针足以证伪）；对 `abstraction` 根**非法**（那是对某个具体模块的判断，换个程序证明不了它）。**不解**手写分片表的死结——求解器的输出是非局部的 |
| **锚定式差分判定**（证 `peak(A) − peak(B) = Δ` 而非绝对峰值） | **否决** | 相消**不精确**且方向是坏的：两个单侧量相减**严格更宽**；全层 vs 选择性重算使 `t*` 跨阶段迁移（活跃集合本身不同，相消为零）；`tp` 变化时 workspace 阶跃使差分误差**大于**任一端。**核心：相消覆盖面与不可验证覆盖面负相关——能消掉的本来就是窄的那些** |

另：用"某配置已知跑通"当锚点做二分搜索，等价于用真机峰值反解，**绕过 P-peak**，不予采用。
框架 OOM 报错文本里的 `tried to allocate X bytes` 是**全案最便宜的旁路**（不需要 profiler、
用户随手一贴就有），已明文排除，只留"这次跑 OOM 了"一个比特。

### 3.2 `PolicyDerived` 侧表

曾设计一张侧表，把源码规范化函数里的派生规则（如 `padded_vocab = ceil_div(vocab, 128·tp)·128·tp`）
抽出来存成条目，供 pass 消费。**否决**，两个理由：

1. 手写条目与自动抽取的条目**在数据上不可区分** ⇒ 它是"把算不出的量改名成派生规则"的同构物；
2. 补一道「每个条目都能在当前 `SourceAST` 上重新推导出来」的门救不了：若该门重跑同一套抽取，
   它**恒真**；若换一套推导，它**不完备**。而且它是加载期门去查编译期产物，**相位是错的**。

**现在**：需要的 pass 在自己的策略绑定处**现场调 PE**（正文 §3.5）。没有可被手写的中间制品。

### 3.3 按 microbatch 折叠 liveness

用「稳态在飞 microbatch 数 × 每 microbatch 激活字节」的解析式代替逐 microbatch 实例化，
可省 `mb` 倍。**否决**：它引入**第二份 liveness 实现**（解析式 vs 事件驱动），
与"单一求值器"同型的失守；且它对 `timing_dependent` 边、跨 microbatch alias、
1F1B 的非稳态首尾段都不成立。

**但要挑明**：这是预算撞上限时**唯一还没用的杠杆**。届时必须显式裁决，不许悄悄用。

## 四、人工例外条款的清扫记录

正文 §11.5 现在是一份**前瞻性的形态黑名单**。它的来源是下面这份逐条清扫记录——
每一条都曾真实存在于某一版提案里：

| # | 曾经的条款 | 处置 |
|---|---|---|
| 1 | 反向不同构时的人工裁决通道 | 删除，代以三类归属（正文 §7.2），三个出口无一是放行 |
| 2 | 新增注册条目"每条必须解释为新算子族，且有责任人" | 删除，代以 `G-Z1a/b` |
| 3 | `direction: nominal` | 删除。它使区间塌成点——两轮评审都没点名的活口子 |
| 4 | 越域"降级 + 人声明方向" | 删除。且单侧界的另一端必须显式标"不可计算"，不得默认 0 |
| 5 | 时间侧"非单调告警" | 删除告警形态；取阻断。makespan 已改 `Sample[Float]`，不进该射程，两者不冲突 |
| 6 | 双侧扫描得到的 makespan"区间" | 改类型为 `Sample[Float]`：不参与区间算术、不可与容量比较、不进 OOM 链 |
| 7 | "PySub 差分测试若不被允许，退化为人工评审" | 删除该退路。若不可行 ⇒ PySub 规格没有机器验证手段，写进能力边界 |

### 6.1 十组互斥修法：我的裁定与理由

台账明确不替裁决者选。逐条裁如下：

| # | 问题 | 裁定 | 理由 |
|---|---|---|---|
| 1 | `G-B3a` 该降级还是该恢复为门 | **两者都不选：收窄断言** | 反例（源码显式写的 `all_reduce` 被 PE 直接读出，`roots` 不含 `replication`）说明原断言**过强**，不是分类问题。加限定语「由 `Pass_shard` 合成的」之后，它重新成为 P4 的后置条件 |
| 2 | `G-T1` 的方向不对称改不改 | **不改（保留软方向）** | 改成"真机有而我们没有 ⇒ 硬失败"会让**任何未建模 op**（`TransData`、`Cast`、内存搬运——方案明说不建模）硬失败，门当场不可用；且它会使 `G-N2` 塌进 `G-T1`，丢掉唯一的外部独立门。**残余风险明写**：唯一的外部裁判在"欠建模"这个危险方向上永远是软的。<br>**更好的走法（未采纳，留待第五轮）**：新增族内计数门——对每个**已建模的 op 族**断言预测计数 == 真机计数，它既保住 `G-T1` 的软方向，又把 `G-N2` 一般化 |
| 3 | P5 兜底：强制来源④ vs 取单侧 | **分情况，按"定义式上界是否真的写得出"** | 碎片与池划分**写得出**（组合上界：活跃块数 × 最大粒度）⇒ 走新增的来源⑤；`workspace`、`framework_reserve` **写不出**（与任何可见张量集合无函数关系，唯一为真的无声明上界是容量本身，那是平凡的）⇒ 取单侧。**这一分歧的实质是经验问题不是原则问题**，逐量判即可 |
| 4 | `CalibrationSet` 退化填法的堵法（三选） | **取"张成性 + 留一交叉验证"** | 它无新阈值、不与可用性对立。"memory 通道只能支撑 `vendor_documented`"这条**不采纳**——报告自己写"单独执行等于自杀，必须与 `G-M2` 的可达性证明同时进入方案" |
| 5 | `G-L1` 要检查器还是要门 | **要检查器（正文原文）** | 要门则现有层序至少两层站不住（G0.5 并入 G1、G2 与 G2.5 合并），而那两层的独有不变量是真实的。**残余明写**：`G-L1` 因此抓不到"用一条平凡不变量为任意层辩护" |
| 6 | `unverifiable_coverage` 的 `U` 定义 | **取代数可判定的量集，并拆两个数** | 两个修法不互斥：换掉被度量的对象（去掉"显著"这个隐藏阈值）与拆成字节/成员资格两条通道可以同时做，已同时做 |
| 7 | allocator 复刻背哪个根 | **维持 `declared_semantics`**，但 Θ 分子不再承担这件事 | `θ_abs` 度量的是"**人工判断**占比"，`size_unverifiable` 度量的是"**无残差来源**占比"——两种不同的病，各有各的数。pass 合成的五大块（主副本、梯度桶、重算副本、梯度值、通信 buffer）在 Θ 上隐身是**对的**，它们由 `S_∞` 与 `size_unverifiable` 接住 |
| 8 | 四角 liveness：条件化 vs 抬高上限 | **条件化** | 抬高 `G-R2` 上限要求重新论证 10⁷ 的来历，而正文自曝该数"是推的不是测的"。用一个已存在的强制报表行（TD 字节占比）做门控，不新增 Θ |
| 9 | `inf_interleave` 的 alias 修法：丢弃 vs 合并 | **合并（取最粗划分）** | 合并后求和仍精确 ⇒ 不吃 `own_residual` ⇒ **不落兜底** ⇒ `true`（会 OOM）在类型上恢复可达。丢弃则整块不计，下界过松且仍要吃残差 |
| 10 | 禁用词自违的处置 | **逐处改写**（尚未执行，进档 3 待办） | 在 §0.1 给禁令加"按语境判断"的按语，与 §11.5「按名字禁是禁不住的，按形态才行」的立论自相矛盾 |

### 6.3 这个过程有没有在收敛

**没有明显收敛。** 第三轮产出约 60 条，第四轮约 50 条，第四轮里还有相当一部分是**第三轮修复自己引入的**

**但性质在变**：第三轮的发现多是"某处有逃逸口"，第四轮的发现多是"两处规定不能同时为真"。
后者是**合并期的必然产物**，且**有限**——它的上界是构件之间的交互对数，而不是无穷。

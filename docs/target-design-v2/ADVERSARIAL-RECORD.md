# 对抗记录（设计文档的旁路档案）

> 设计文档 `index.html` 只讲**方案本身**。这份档案留住它是怎么被打出来的——
> 哪些做法被试过并否掉、哪些论证塌过、哪些结论被推翻过。
>
> **它不是设计文档的一部分**，实施时以 `index.html` 为准。这里只回答一类问题：
> 「这条为什么是现在这样，而不是那个更自然的写法？」

**纪律**：全过程**未读现有实现代码**，也未执行任何代码。理由——委托方在做重构，
现有实现与目标形态可能差异极大，读它会污染对新方案本身的评判。

---

## 一、过程

四轮对抗，每轮「提案 → 反驳 → 仲裁」。

| 轮 | 做了什么 | 主要产出 |
|---|---|---|
| 1 | 红队 48 问 + 六判据 + 五种作弊手法；反驳给出 8 个反例 | 确立**零逃逸六判据**，判据 5（代价单调性）定为硬要求 |
| 2 | 按反例重写提案 | PE / π₀ / provenance 代数的雏形 |
| 3 | **四流并行修复**（policy-free 支点 / provenance 代数 / 门体系 / 规模与缺输入）+ 仲裁裁定书 | 层序改动、`readability`、`G-B1a`、门编号重编、能力边界 E |
| 4 | 攻第三轮新引入的面 + 审四条未检验候选 + 五元组一致性 | P5 兜底改单侧、`G-M2`、§10.2b 不对称、推翻 `G-N2` 的降级 |

三条外部裁定的硬前提贯穿全程（正文 §0.1）：真机对照仅限 op 级 time 记录（**P-oracle**）；
端到端峰值标量同样排除（**P-peak**）；不接受任何人工例外条款（**P-noexc**）。

## 二、被推翻过的结论（按严重度）

### 2.1 「无机器残差 ⇒ 保持点值」——两个独立反驳者同时撞到

**曾经的写法**：`evidence.grade ∈ {vendor_documented, reconstructed}` 时 `own_residual`
无机器来源 ⇒ **不伪造一个数** ⇒ 该量的 interval 保持点值。

**为什么错**：不可验证的那部分字节（allocator 行为、融合 workspace、通信复刻、分桶规则）
对区间宽度的贡献**恰好为零**。于是"峰值只有区间形态"这条不变量被架空——
输出是一个**伪装成区间的点估计**，而它最容易错的方向（低估）正是用户最想采信的方向。

**现在**：兜底改「取单侧」（正文 §2.5 P5、决策 D15）。代价是标定不足时说不出"装得下"——
这是有意的，`CalibrationSet` 由此成为真正的交付物。

### 2.2 `PolicyStateBinding` 的「被写过」是语法判定

**曾经的写法**：读取任何 import 后**被写过**的模块级可变全局，若不在声明表里 ⇒ 阻断。

**反例**：

```python
_STATE = {'tp': 1}                      # 模块级绑定一次
def init(...): _STATE['tp'] = world_size   # 只改字典内容，绑定从未被重写
```

"被写过"为假 ⇒ 不阻断 ⇒ PE 把 `tp` 读成 1，provenance 是 `source/exact`。
**策略污点从未生成，policy-free 断言平凡通过，而答案是错的**，且每个指标都变好。

**现在**：判据画在**读**的一侧（正文 §3.4）。

### 2.3 `G-N2` 被误判为 `G-T1` 的「特例投影」

曾按「共用同一条 trace」把桶数对照门降级、不独立计数。**反例**：分桶欠预测（我们 4、真机 6）时，
我们的序列**仍是**真机序列的合法保序子序列 ⇒ `G-T1` 绿；而计数不等 ⇒ `G-N2` 红。

**教训已写进正文 §12.3**：子序列断言非对称（只惩罚"多"），等式断言严格更强。
数门的判据是「能否构造缺陷使 A 红而 B 绿」，不是「它们读同一份数据吗」。

### 2.4 门数算错

曾写「31 条目 / 真门 26」，而按 oracle 分布之和是 31——自相矛盾。
重数：**44 条目、后置条件 3、报告项 1 ⇒ 真门 40**，其中只有 5 道拿真机数据当裁判。
连带修掉「§7.3 叫后置条件、门表里标门」的分类冲突。

### 2.5 `peak_lower` 的方向搞反过

曾写「不补下界的话，本方案永远只能证明装得下、永远不能断言 OOM」。
把碎片算进来之后**正好倒过来**（正文 §10.2b）：`reserved = allocated + 碎片`，碎片 ≥ 0
⇒ 「会 OOM」可判定（碎片救不回来），「装得下」当且仅当碎片模型有上界。

### 2.6 死掉的论证（结论保留，理由换掉）

| 论证 | 为什么死 | 换成什么 |
|---|---|---|
| 「分层是为了支持交互式 what-if」 | 产品形态确定为"配好配置直接出结果"，无此消费者 | `G-L1`：一层存在 ⟺ 它是某条不变量唯一能被陈述的位置 |
| 「反向必须派生，否则改重算配置会使 CoreIR 缓存失效」 | 同上 | policy-free 是 CoreIR 唯一的断言点，写进去就没地方陈述它了 |
| 「活跃集合在真机 allocator dump 里可观测」 | P-oracle 下为假 | 归因口径改为对**模型**可扰动，并声明它不使显存模型可证伪 |
| 「注册要被四道门打」 | P-oracle 删掉了其中两道 | 两道门；storage/placement 面的注册项没有独立对照物 |
| 「真机对照是唯一正确性判据」 | 对显存侧为假 | 时间链有 oracle；显存链全部改称**自洽性检查** |

## 三、被试过并否掉的做法

### 3.1 四条「第二把尺子」候选

P-oracle + P-peak 之后显存链无外部裁判，于是找过四条替代 oracle。**记在这里免得重新发明**：

| 候选 | 裁定 | 为什么 |
|---|---|---|
| **allocator 停顿显形为 `O` 的同流间隙**（只比对越水位点的序号，不做时长→字节反解） | **降为报告项** | 分配是**主机侧**动作，设备间隙 = 主机停顿 − 排队深度，而**排队深度不在 `O` 里**；且"这个间隙是设备 malloc 还是调度气泡"的判别需要一个新阈值，落进已被消灭的阈值门射程 |
| **op 计数与位置约束 liveness 成员资格** | **采纳一半** | gather / 重算侧成立（有真实设备 op）；**释放侧不成立**——`FreeParam` 是主机侧归还，在 `O` 中不存在 ⇒ `free_policy` 的 `at_step_end` 与 `never` 结构性不可分辨（已进正文 §8.2 与诚实边界） |
| **判别式探针**（主动造 oracle，探针不必是目标模型） | **窄采纳** | 只对 `replication` 根合法（规则是全称量化的，小探针足以证伪）；对 `abstraction` 根**非法**（那是对某个具体模块的判断，换个程序证明不了它）。**不解**手写分片表的死结——求解器的输出是非局部的 |
| **锚定式差分判定**（证 `peak(A) − peak(B) = Δ` 而非绝对峰值） | **否决** | 相消**不精确**且方向是坏的：两个单侧量相减**严格更宽**；全层 vs 选择性重算使 `t*` 跨阶段迁移（活跃集合本身不同，相消为零）；`tp` 变化时 workspace 阶跃使差分误差**大于**任一端。**核心：相消覆盖面与不可验证覆盖面负相关——能消掉的本来就是窄的那些** |

另：用"某配置已知跑通"当锚点做二分搜索，等价于用真机峰值反解，**绕过 P-peak**，不予采用。
框架 OOM 报错文本里的 `tried to allocate X bytes` 是**全案最便宜的旁路**（不需要 profiler、
用户随手一贴就有），已明文排除，只留"这次跑 OOM 了"一个比特。

### 3.2 `PolicyDerived` 侧表

曾设计一张侧表，把源码规范化函数里的派生规则（如 `padded_vocab = ceil_div(vocab, 128·tp)·128·tp`）
抽出来存成条目，供 pass 消费。**否决**，两个理由：

1. 手写条目与自动抽取的条目**在数据上不可区分** ⇒ 它是"把算不出的量改名成派生规则"的同构物；
2. 补一道「每个条目都能在当前 `SourceAST` 上重新推导出来」的门救不了：若该门重跑同一套抽取，
   它**恒真**；若换一套推导，它**不完备**。而且它是加载期门去查编译期产物，**相位是错的**。

**现在**：需要的 pass 在自己的策略绑定处**现场调 PE**（正文 §3.5）。没有可被手写的中间制品。

### 3.3 按 microbatch 折叠 liveness

用「稳态在飞 microbatch 数 × 每 microbatch 激活字节」的解析式代替逐 microbatch 实例化，
可省 `mb` 倍。**否决**：它引入**第二份 liveness 实现**（解析式 vs 事件驱动），
与"单一求值器"同型的失守；且它对 `timing_dependent` 边、跨 microbatch alias、
1F1B 的非稳态首尾段都不成立。

**但要挑明**：这是预算撞上限时**唯一还没用的杠杆**。届时必须显式裁决，不许悄悄用。

## 四、人工例外条款的清扫记录

正文 §11.5 现在是一份**前瞻性的形态黑名单**。它的来源是下面这份逐条清扫记录——
每一条都曾真实存在于某一版提案里：

| # | 曾经的条款 | 处置 |
|---|---|---|
| 1 | 反向不同构时的人工裁决通道 | 删除，代以三类归属（正文 §7.2），三个出口无一是放行 |
| 2 | 新增注册条目"每条必须解释为新算子族，且有责任人" | 删除，代以 `G-Z1a/b` |
| 3 | `direction: nominal` | 删除。它使区间塌成点——两轮评审都没点名的活口子 |
| 4 | 越域"降级 + 人声明方向" | 删除。且单侧界的另一端必须显式标"不可计算"，不得默认 0 |
| 5 | 时间侧"非单调告警" | 删除告警形态；取阻断。makespan 已改 `Sample[Float]`，不进该射程，两者不冲突 |
| 6 | 双侧扫描得到的 makespan"区间" | 改类型为 `Sample[Float]`：不参与区间算术、不可与容量比较、不进 OOM 链 |
| 7 | "PySub 差分测试若不被允许，退化为人工评审" | 删除该退路。若不可行 ⇒ PySub 规格没有机器验证手段，写进能力边界 |
| 8 | 改策略分类表的保障是"评审 + 进快照" | 删除"评审"，代以 `class_origin` + 退出扫描 |
| 9 | `RuntimeInvariant`"可评审" | 保留通道，删"可评审"这一保障 |
| 10 | trace 对齐的"未匹配 op 忽略清单" | 不设。逐条计数进上界；反方向硬失败 |
| 11 | 策略交换律对照映射 `ψ` 的逐 op 例外 | 不设（`G-X5`）。`ψ` 是人写的，可被调宽到吃掉真实差异，且这么做**使答案形状不变** |

## 五、v3 相对上一版的实质差异

| 位置 | 上一版 | 现在 | 起因 |
|---|---|---|---|
| 分层判据 | "每层只增加一类信息" | `G-L1`：一层存在 ⟺ 它是某条不变量唯一能被陈述的位置 | 旧判据不可证伪 |
| 层数与层序 | S1–S7 七层，融合/精度隐含 | G0 → G0.5 → G1 → G1.7 → G2 → G2.5 → G3 → G4 | 反向模板逐 op 查表 ⇒ op 集合必须先定稿 |
| provenance | 三值枚举 | 两条正交轴 `certainty` × `roots`（八种闭集），三个旧名降为命名投影 | 旧定义把"注册一条算子语义"判成事实 |
| 策略的位置 | 策略作为各层输入 | π₀ 策略正则形 + PGRO 逐 guard 重建义务 | policy-free 需要一个可机器判定的支点 |
| 头号输出 | 峰值标量 + OOM 布尔 | 峰值只有区间形态；`oom_verdict : Q3[Bool]` + 判定阻碍分解 | 无外部裁判 ⇒ 点估计是不诚实的 |
| 验收 | 真机对照为唯一正确性判据 | 时间链有 oracle；显存链无外部裁判，全部改称自洽性检查 | P-oracle + P-peak |
| 诚实边界 | 四条散列 | 一条命名性质**边界 E** + 必须打印的 `unverifiable_coverage` | 四流自曝重叠在同一格 |

## 六、仍然欠的

| # | 欠什么 | 影响 |
|---|---|---|
| 1 | **AST 探针**（语法构件计数 + 三张清单 + policy-tainted guard 的数量与分布） | 决定 PySub 覆盖率、`PolicyStateBinding` 规模、PGRO 工作量与假阻断风险 |
| 2 | **合成图空转基准**（10⁶ 假事件，把每事件成本从假设变成测量值） | 规模对账表对它乘性敏感，最坏实现差三个数量级 |
| 3 | `PolicyStateBinding` 默认拒绝的**假阳性规模**未定量 | 若框架里模块级全局极多，声明表可能膨胀成开集 ⇒ 判据 3 失守 |

**在 1、2 完成前，任何引用探针结果或对账表绝对数值的论证一律无效。**

## R2 · 【靶子·来源④ 扩到 `replication`】对**存在性型**复刻规则，来源④ 的两端**方向倒置** ⇒ `interval.lo > interval.hi`

来源④ 现在的定义（行 389-397）把两端**绑定在语义上而不是绑定在大小上**：

> `lo = 声明成立时的值；hi = 声明完全不成立时该量的无声明上界`

**构造（正文自己在两页之外给了这个例子）**：§2.5 行 463-465（P5 选侧的 bad 框）原文——

> 以 fp32 主副本为例：公式 `4×numel` 本身确定，`modeled` 的来源是"框架**是否真的建了这块**"——没建 ⇒ 真值更小 ⇒ 我们是 `upper`；建得更多 ⇒ 真值更大 ⇒ 我们是 `lower`。

`Pass_precision_opt` 的 `own_roots = replication(master_copy_rule)`（P4 表行 505 等价行）。该规则是一条**存在性断言**："框架为每个参数建一份 fp32 主副本"。代入来源④：

```
lo = 声明成立时的值            = 4 × numel        （主副本存在）
hi = 声明完全不成立的无声明上界 = 0                （主副本不存在 ⇒ 该量的无声明上界就是 0）
⇒ interval = [4×numel, 0]，lo > hi
```

**后果（三条，任一条单独足以否掉本轮对来源④ 的扩域）**：

1. **`cmp` 的两条判据同时成立**。§2.7 行 560-562：`a < b ⇒ true iff a.hi < b.lo`；`⇒ false iff a.lo ≥ b.hi`。端点倒置的量沿区间算术传到 `peak` ⇒ `peak.lo > peak.hi` ⇒ `peak.lo > C_eff.hi` 与 `peak.hi ≤ C_eff.lo` **可以同时为真** ⇒ `oom_verdict` 同时是 `true` 与 `false`。`G-X7` 查的是**操作数类型**，不查端点序，抓不到。
2. **同一族的全部大项都在内**：`replication(remat_rule)`（重算副本存不存在）、`replication(precision_rule)`（fp8 低精副本、`amax`/`scale` 缓冲存不存在）、`replication(dist_fusion_rule)`（合并 buffer 存不存在）、`replication(alias_rules)` 的**逆向读法**（"两个值实际不共享存储"也是一条存在性断言）。这恰好是 `S_∞` 序 1/2/3/5/9 —— 正文自称字节量最大的那一整类。
3. **它把 P5 兜底那个"未受控的二选一"搬进了来源④，而来源④ 不落兜底**。实现者面对倒置区间只能手工挑一端当 lo、另一端当 hi —— 这正是行 466-469 判定"不可执行"的那个二选一。区别是：兜底量进 `S_∞`、进首页强制清单、进判定阻碍分解；**来源④ 的量三处都不进** ⇒ 同一个自由度换了个位置，**且新位置比旧位置隐蔽**。这是台账反复出现的那个模式的第八次发作。

**为什么四轮没发现**：来源④ 原本的适用域只有 `{abstraction, declared_semantics, assumption}`——这三种根都是**关于某个量取值多大**的断言（"这个模块等价于逻辑 Linear"、"这个融合 kernel 的 workspace 是这么大"、"负载是均衡的"），其"声明不成立"确实给出更大的上界。`replication` 是**第一个含"该对象存不存在"语义的根**（P4 的存在位下传是整篇的承重墙），扩域时没有人问"存在性断言的两端还满足 lo ≤ hi 吗"。

**最小修补（零新构件）**：来源④ 的两端**按值排序而非按语义命名**——
```
v_hold := 声明成立时的值;  v_fail := 声明完全不成立时的无声明上界
interval := [ min(v_hold, v_fail), max(v_hold, v_fail) ]
```
并加一条 schema 断言（无阈值、可机器判、加载期执行）：**`∀ q : interval(q).lo ≤ interval(q).hi`，违反 ⇒ 阻断**，与 `G-X7` 同型同相位。副产物：对存在性型规则，来源④ 自动给出 `[0, 4×numel]`，宽度 = 该项全部字节 —— 这是**诚实的**（我们确实不知道框架建没建这块），并且它使 `S_∞` 序 1/2/3/5 从"不可计算"变成"可计算但宽度等于自身"，与 R5 汇合。

## R5 · 【靶子·alias 的 `[最粗, 最细]`】区间宽度恒 ~3–4 倍且**永不可收紧**，而它同时退出了 `S_∞` 清单与判定阻碍分解的两段 ⇒ `G-M2b` 是**真·恒红**，正文声称的"会自己变绿"为假

**先说攻不动的一半**：`hi` 端"每个 `TensorId` 各占一块"**确实是上界**。in-place 累加（`grad.add_(x)`：1 storage / 2 TensorId ⇒ 计 2 次）、视图链（`qkv → split → reshape → transpose`：1 storage / 多 TensorId ⇒ 各计一次）、跨 microbatch 复用（同一 workspace 被 `mb` 次实例化 ⇒ 若 `TensorId` 是每值一个则计 `mb` 次）——**三种情形都只会让最细划分的和更大**，方向正确。**攻不动，理由：最细划分下每个真机 storage 的字节被至少计一次。**

**成立的攻击在宽度与可见性上**：

**(a) 宽度是结构性的、恒定的、与标定进度无关。** 构造（基准配置本身即可）：transformer 前向里 qkv 投影输出经 split → reshape → transpose，一块 storage 对应 ~7 个 TensorId，最细划分的和 ≈ 3× 最粗；每个 in-place 残差加与 in-place 激活各贡献 2×；连续梯度缓冲 + 每个参数梯度的 view ⇒ 2×。⇒ **`peak_allocated.hi / peak_allocated.lo` 结构性地落在 2.5–4 之间，在每一份真实训练配置上都如此。**

⇒ `oom_verdict = false` 要求 `peak_reserved.hi ≤ C_eff.lo`，即真实峰值 ≲ 25–40% 容量。**而用户来这个工具，问的恰恰是接近满载的配置**（§2.8 行 614：「"装得下"正是用户来这里要的那句话」）。⇒ **"装得下"在任何值得问的配置上恒不可达。**

**(b) 这个宽度永远收不紧。** §14.3 明写「alias / in-place / 存储复用判断**无验证手段**」。alias 没有标定点 ⇒ 永远拿不到来源③ ⇒ `evidence.grade` 永远停在 `reconstructed` ⇒ §2.5 行 481-483 的产品路线论证（「标定一个量 ⇒ 它获得来源③ 的真实残差 ⇒ 它退出单侧 ⇒ `peak.hi` 向可计算前进一步」）**对 alias 在原理上不适用**。

**(c) 于是 §10.2b 行 1683-1688 的"诚实交代"是错的。** 原文：「标定工作一旦推进到外部碎片，`G-M2b` 会自己变绿——**它是标定路线图的验收条件，不是免责声明**」。**外部碎片被标定之后 `G-M2b` 仍然红**，因为 alias 的 3–4 倍宽度使 `peak.hi ≤ C_eff.lo` 在任何非玩具配置上为假，而 alias 不在任何标定路线图上。⇒ `G-M2b` 是一道**没有变绿路径**的门。

**(d) 最坏的一处：这个宽度从全部报表口径里消失了。** alias 走来源④ ⇒ **不落兜底** ⇒
- 不进 `S_∞` ⇒ **不进首页强制字段「`S_∞ ∩ live(t*)` 的完整成员清单」**；
- 不进 §10.3 判定阻碍分解**第一段**（"去获得一个界"）；

## R6 · 【靶子·`inf_witness`】它可以是平凡的 `0`；无"与该量有关系"的检查；且**排除 `calib` 使标定反而使形状变差**

行 411-416：兜底量必填 `inf_witness : Expr`，`roots(inf_witness) ⊆ {source, configured, transcribed} ∧ certainty(inf_witness) = exact`。

**(a) 二难：`0` 合法则 S2 原样保留，不合法则两个 verdict 同时不可达。**
字面量 `0` 的 `roots = ∅`，而 `∅ ⊆ {source, configured, transcribed}` **为真** ⇒ 第一条断言通过。第二条 `certainty(0) = exact` 取决于 §2.5 行 356-359「叶子 `Q` 的 `certainty` 由其**根种类**定」——该规则**逐条列举根种类，没有一条覆盖"无根"**，兜底句是"其余根 ⇒ `modeled`"，而 `0` 连"其余根"都没有。⇒ `certainty(0)` **无定义**。两种补全都坏：

- 读作 `exact`（把无根字面量当 `Primitive`）⇒ **`inf_witness := 0` 对每个兜底量都合法** ⇒ r5 S2 构造 A 原样成立：`peak.lo ≈ Σ 参数本体`，`C_eff.hi ≈ HBM` ⇒ `true` 在任何做了分片的配置上不可达。**S2 的病只是多打印了一列 `0`。**
- 读作 `modeled` ⇒ 全部非负兜底量（其真实可证下界就是 0）**都给不出合法 `inf_witness`** ⇒ 按行 415 「`interval.lo` 也标"不可计算"」⇒ `peak.lo` 不可计算 ⇒ **`true` 也不可达** ⇒ `G-M2a` 与 `G-M2b` **同时恒红**。

**(b) 没有任何检查要求 `inf_witness` 与该量有关系。** schema 只断言它的根种类与 certainty。⇒ `inf_witness(external_fragmentation) := ModelSpec.hidden_size`（`roots = {configured}`、`exact` ✓）**完全合法**，是一个与外部碎片毫无关系的数。

**构造（判据 5 反向 + 判据 1 反向）**：实现者对每个兜底量把 `inf_witness` 填成一个**尽可能大的**合法事实表达式（`ModelSpec` 里现成的 `numel`、`hidden × seq × batch` 之类）⇒ `peak.lo` 抬高 ⇒ `peak.lo > C_eff.hi` 变得容易 ⇒ `oom_verdict = true` 可达 ⇒ **`c3 = (oom_verdict ≠ undetermined)` 由 false 变 true**（`clean` 向量的一个分量严格上升 ⇒ 违反 `L-mono`），`G-M2a` 拿到 fixture，首页 verdict 从"未定"变"确定"。
**而这个方向零风险**：§0.1 规定唯一的外部信号是用户自报的 OOM 布尔事实，且它**只能反证 `false`**（行 62-63 的 falsification 判据是「真机 OOM 而 `peak.hi < C_eff.lo`」）。⇒ **一个虚假的 `true` 在本方案下永远不可能被证伪。** 判据 1 与判据 5 同时失守，且方向正是"工具骗人"那一侧的镜像（这次是假 OOM，使人白白买卡）。

**(c) 排除 `calib` 是一处硬伤，且它使标定的代价方向反了。** 允许集是 `{source, configured, transcribed}`，**不含 `calib`**。而 §2.5 行 357 自己写「`calib ⇒ exact`（值来自实测点）」——`calib` 与前三者在 certainty 上同级。构造：`alignment_overhead` 的自然下确界证人是"最小对齐粒度 × 活跃块数"，而对齐粒度是 allocator 复刻规则的常数；**一旦它被标定**，其根变成 `calib` ⇒ **该证人失去 `inf_witness` 资格** ⇒ 该量按行 415 两端皆不可算 ⇒ 落回 `S_∞`。⇒ **标定一个量使答案形状变差**，与 §2.5 行 481-483 的产品路线论证方向相反。这条排除看不出任何理由，像手滑。

**最小修补**（三条，全部零新构件）：
1. 允许集加 `calib`（`calib ⇒ exact` 已由 P2 保证，加它不放松任何东西）。

**(b) `BLK-SYNTAX` 使 §2.4 与 §11.1 直接矛盾。** §2.4 行 313 的 `readability` 定义逐字是：

> `PARTIAL`  可解析入口，但体内有**一个或多个 `BLK-*` 站点**（站点集随之记录）

—— **任意** `BLK-*`。而 §11.1 说 `PARTIAL` 只承认能力边界类。`BLK-SYNTAX`（体内出现 PySub 之外的语法构件）**不在能力边界类的三个成员里**（它有 AST，只是我们的子集读不懂 ⇒ 不是"无 AST 的被调者"；不是 DATAGUARD；不是 Opaque）。⇒ 一个体内含 `BLK-SYNTAX` 站点的模块，按 §2.4 是 `PARTIAL`，按 §11.1 不是。**`readability` 是"机器计算、用户不可填"的字段，它有两个互相矛盾的生产规则。**

**(c) `BLK-UNRECONSTRUCTIBLE` 的两读都有硬后果，而正文没给归属。**
- 读作**能力边界类** ⇒ 一个 guard 重建不出来就能把整个模块降成 `PARTIAL` ⇒ 其未求值站点按 §2.4 校正② 各成独立 `abstraction` 条目、按 P5 兜底取单侧 ⇒ 落 `S_∞` ⇒ **"装得下"不可达**。而 §11.1 的连带限定的**立论**恰恰是"否则少写一条声明就能把整个模块降成 `PARTIAL`"——同一个漏洞换个阻断码就成立。
- 读作**事实源缺项类** ⇒ 直接阻断整次编译、**无注册通道** ⇒ 而 `attention_backend` / `*_fusion` / `Π_precision` 这类 guard 走 PGRO 失败正是 `BLK-UNRECONSTRUCTIBLE` 的常规出口（§4.2）⇒ **整类框架不可编译**。

**最小修补**：把二分改成**每个阻断码 schema 必填的一列** `blk_class ∈ {fact_source_gap, capability_boundary}`（闭集、无第三值、缺失即加载期阻断），并**逐码给值**（含三个当前无名的阻断码——先给它们名字）；§2.4 的 `PARTIAL` 定义改为「体内有一个或多个 `blk_class = capability_boundary` 的站点」，`fact_source_gap` 站点一律使整次编译阻断。`G-E4`（阻断有效性套件）的量词随之覆盖新列 —— 它本来就是"每个 `BLK-*` 各有触发输入"，加一列断言零成本。

## R12 · 【靶子外】`θ_abs` 的两处修复各落一半：分子仍用 `roots`（饱和未消）、分母改用 `.value`（点估计在第三个位置复活），且三处口径互不一致

**(a) `roots → own_roots` 没改。** 行 1739：
```
judged := Σ_{i ∈ live(t*) : {abstraction, declared_semantics} ∩ roots(size_i) ≠ ∅} size_i.value
```
仍是 `roots`。而**同一个框**行 1765-1770 自己论证了饱和、给出了 `own_coverage(r)`、并把它**只放进 ledger 与首页第二列**。⇒ **门的分子仍然饱和**。

**构造**：把第 0 层的任意一个模块判成逻辑原子（`readability = FULL` ⇒ §2.4 表给 `abstraction` 根），或该层含一个无 AST 的融合 kernel（⇒ `declared_semantics` 根）⇒ 由 P1（`roots(f(x)) = ∪roots(xᵢ) ∪ own_roots(f)`）与 P8（只升不降），残差流使**该点之后的每一个激活字节**都带该根 ⇒ `judged / base → 1` ⇒ 对任何 `θ_abs < 1` **恒触发**。r5 S5 的具体载体（`Pass_impl_select` 的 `own_roots`）已被 P4 表改成 `replication(impl_select_rule)` 而失效 ✓，**但机制本身原样存活**，只需一个真实的 `abstraction` 根即可复现。判据 4 的新一问同样不过：抽象集合不随并行配置变 ⇒ 在目标配置族上 `judged/base` 近似常量。

**(b) 分母口径三处不一致。**

| 行 | 内容 |
|---|---|
| 1738（注释） | 「分母：与分子同口径的 **`size.lo`** 之和 —— **恒可计算**，且比值恒 ∈ [0,1]」 |
| 1739-1740（公式） | `size_i.**value**` |
| 1759（bad 框） | 「**钉死为**分子分母同口径的 **`size_i.lo`** 之和」 |

**三处，两个口径。** 而 `.lo` 与 `.value` 的性质完全不同："恒可计算、比值恒 ∈ [0,1]"这两条**只对 `.lo` 成立**（`.value` 是点估计，比值也在 [0,1] 但"恒可计算"的论证是针对 `.lo` 写的）。

**(c) 更深的一处：`.value` 把点估计放进了唯一一道 Θ 门的分子分母。** §2.3 行 231 定义 `value : T = π₀ / **当前配置下的求值结果**`。对一个落 P5 兜底的量，`value` 就是"**我们算出的那个点估计**"——正是 §2.5 行 445-447 逐字判定为病的东西（「读作"我们算出的那个值"⇒ 由一个**不承担可证伪义务、没有宽度、没有证据等级约束的点估计**单独决定」）。`value` 没有 `inf_witness` 那样的证人义务、没有任何 schema 约束。

⇒ **S2 的病在第三个位置复活**：区间宽度（原病）→ 下界端点（r5 S2，已用 `inf_witness` 修）→ **Θ 门的口径**（本轮）。而 `θ_abs` 的实测比值是 §10.4 行 1752 规定的**首页强制打印项**。

**最小修补（一处改动同时解 a/b/c）**：
```
judged := Σ_{i ∈ live(t*) : {abstraction, declared_semantics} ∩ own_roots(producer(size_i)) ≠ ∅} size_i.lo
base   := Σ_{i ∈ live(t*)} size_i.lo
```
`own_roots` 消灭饱和（(a)）；`.lo` 恢复"恒可计算 / 恒 ∈ [0,1]"的论证（(b)(c)），且 r5 S13 反对 `.lo` 的理由（"落兜底的量 `.lo` 为 0 ⇒ 门对它们失明"）**在有了 `inf_witness` 之后已经不成立**——`.lo` 现在是一个有证人的数，不再恒为 0。**两处修复本来就该合起来读，分开落就各自变成了病。**

## R13 · 【靶子·凸包域片】凸包在**离散维**上无定义；高维下诚实标定也**恒越域** ⇒ 连 `G-M2a` 的 fixture 都拿不到

`G-X3`（§12.2 与 §11.1 行 1856-1861）：`域片 := 该量的标定点集在参数空间中的**凸包**`；越域 ⇒ 阻断。

**(a) 离散维上凸包无定义。** 标定域片的参数空间**必然含离散维**：§10.1 的分级回退第二级逐字是「形状/**类型**插值」⇒ `dtype` 是域片的一维；`CalibKey` 必填 `measured_quantity`（闭集）；§13.3 档 D 点名的 `attention_backend` / drop 策略 / 实现族替身也进定价。`conv({fp16, fp8})` **没有定义**。两种补全都坏：
- 把离散维**排出**凸包 ⇒ 域片对它无约束 ⇒ **用 fp16 的标定点给 fp8 定价，越域检测在最该生效的一维上失效**（而 fp8 workspace 与 fp16 workspace 差一个量级）；
- 把离散维**留在**凸包里 ⇒ `G-X3` 在加载期无法求值 ⇒ 按 §3.1 的"缺失≠空"原则该阻断 ⇒ **加载期恒阻断**。

**(b) 高维凸包使诚实标定也恒越域。** 构造：域片维数 `D`（形状维 3–5 + dtype + 若干 attrs，`D ≥ 5`）。真实标定点集通常是**一条曲线**而非网格——工程上等比放大 `(seq, batch)`、固定 `heads`。⇒ 凸包是一个**低维单纯形**，在 `D` 维空间里体积为 0 ⇒ **任何不在该曲线上的目标配置越域** ⇒ 阻断。而 §10.2b 的洁净配置要求「全部算子 Tier 1」，Tier 1 需要定价 ⇒ **`G-M2a` 的 fixture 也拿不到** ⇒ 由 R7(b) `G-M2a` 本已只能由玩具满足，现在连玩具都要为它的每个算子精确落在凸包内。

⇒ 用户被激励做的事是：**为目标配置补一个恰好落在它上面的标定点**。凸包随即含它 ⇒ 通过。这**不是**退化填法（留一交叉验证会给出真实的外推残差 ⇒ 区间变宽 ⇒ 形状变差 ✓，判据 5 方向正确），但它使标定成本从"建一个域片"变成"**每个配置各标一次**"——与 §13.3 的 `2k → 34` 成本论证、与"配好配置直接出结果"的产品形态都不相容。

**最小修补**：域片 = **离散维上的精确匹配 × 连续维上的凸包**（两段式，机器可判、无阈值）：`域片(q) := { p : p.离散面 ∈ {标定点的离散面} ∧ p.连续面 ∈ conv(同离散面的标定点的连续面) }`。这同时解掉 (a)（离散维不做凸包）与 (b) 的一半（每个离散组合各自的连续凸包维数更低但也更贴合）。(b) 的另一半必须**显式承认**：凸包域片使"从未标定过的配置一律阻断"，这与 §10.1 的 roofline 初始定价通道**必须**并存 —— 行 1860-1861 已经写了这条区分（「从未建立过域片的算子族走 roofline 初始定价，**不阻断**」），**但它只覆盖"该算子族一个域片都没有"的情形，不覆盖"有域片但目标点在凸包外"** ——而后者才是常态。补一句：**当越域距离使该量退回 roofline 级仍可定价时，走 roofline + P5 兜底单侧，不阻断**；只有连 roofline 都缺参数时才阻断。

这与 `G-M1` 的双向形式（见 R7 修补 2）**是同一把尺子**：一道门只有在"能红也能绿"时才携带信息。它可机器执行、有阻断出口、无需定义"方差多大"。副产物：它会立刻把 `θ_res`（R4）与 `θ_abs`（R12）判红，而那正是判据 4 想要的结果。

# 2. **修复之间相乘产生的**（这一类最危险）

## M1 · 来源④ 扩到 `replication`（为救 alias）× `S_∞` 表保留"无无声明上界" ⇒ **`S_∞` 的成员资格成为实现者的自由选择**

两条修复各自读都成立：为了不让 alias 锁死全链，把来源④ 的适用域扩到 `replication`（行 390）；为了不让"碎片是唯一障碍"这句错话误导路线图，保留 `S_∞` 十一行清单并逐条给出"为什么四个来源都不适用"（行 1641-1652）。

**相乘后**：适用域是一个**纯语法谓词**（`roots ∩ {...} ≠ ∅`），而"来源④ 实际能不能给出两端"是一个**语义问题，没有机器判据**。同一个 `replication` 根，正文对 alias 说"两端本来就可算"、对序 1/2/3/5 说"无无声明上界"。⇒ 实现者可以对**任意**兜底量宣称来源④ 适用并给一个平凡 hi，把它移出 `S_∞`。

**后果链（全部是本轮新加的构件）**：`S_∞` 清单（首页强制）↓、`blocking_set_size` ↓、§10.3 从第一段跳到第二段、洁净配置第五条可满足、**`G-M2b` 由红变绿**、首页那句"给不出装得下"消失。**判据 5 硬失败：零成本、每个指标都变好。** 详见 R3。

**为什么这是相乘而不是单条**：单看来源④ 的扩域，它是对的（alias 确实需要它）；单看 `S_∞` 表，它也是对的（那些量确实没有非平凡上界）。**只有把两者放在一起读，才会发现"适用"这个词在两处指的不是同一件事。** 而没有人会同时读 §2.5 P5 与 §10.2b 的表格 —— 它们相隔 1250 行，且分属"代数"与"输出"两章。

## M2 · 来源④ 扩到 `replication` × P4 的**存在位下传** ⇒ 端点倒置

P4 是全篇的承重墙：`replication` 根被用来表达"**这个节点为什么存在**"（§2.5 P4 连带定案：「判据是"这个节点**为什么存在**"，不是"它的字节**怎么算**"」）。来源④ 的两端表述是"声明成立时的**值** / 声明不成立时该量的**无声明上界**"——它假设声明失败使该量**变大**。**对存在性断言，声明失败使该量变成 0。**

⇒ `lo > hi`。详见 R2。**这是两条修复的语义前提互相不兼容**：P4 让 `replication` 承载存在性，来源④ 假设它承载数值。扩域时把 `replication` 当成第四种"对世界的断言"塞进去，没有人回头核对 P4 给它的是什么语义。

## M3 · `G-A*` 量词扩张 × `G-C2` 降级 × `G-N2` 降为 `G-T1` 的实例 ⇒ **G2 层的独有不变量集合为空 ⇒ 按 `G-L1` 停止条件 G2 必须与相邻层合并**

三条修复分别在 §12.1（量词扩到"一切带阻断出口的断言"，新增 `G-A*`）、§12.3（`G-C2` 降级为后置条件）、§12.2 + §12.3（`G-N2` 是 `G-T1` 的实例，不独立计数）。

**G2 ShardIR 的独有不变量只有两条**（§1.3 行 146）：
1. 「placement 类型健全（无失配）」 = **`G-C2`**，已降级为后置条件，理由是"是 `Pass_shard` 自己的终止条件"；
2. 「桶数 = 真机归约算子个数」 = **`G-N2`**，已被判为 `G-T1` 的实例、不独立计数。

**相乘后的构造**：
- `G-A*` 把这两条编号并纳入 `G-M1` 的量词 ⇒ `G-M1` 断言它们各有规格级 red fixture。第 1 条**按 §12.3 自己的降级理由就没有**（它是算法的终止条件）⇒ `G-M1` **在自己的第一次扩张后立刻失败**；

## M6 · `.hi` 侧换构造（"存活区间取并"）× roofline 初始定价落 P5 兜底单侧 ⇒ `peak_allocated.hi` 不可算，而**该阻碍不在 `S_∞ ∩ live(t*)` 的口径内**

§10.2 行 1437：`peak_allocated.hi := sup_interleave(size := size.hi, **live := 存活区间取并**)`，其中「每条 `timing_dependent` 边把受影响 storage 的存活区间**取并**」。

**先说攻不动的一半**：在非单调轴上，取并**确实**给出与时长取值无关的结构上界，比"四角取 max"（抽样）严格更好。**攻不动，理由：区间并是保守的，且论证不依赖单调性。**

**成立的攻击**：取并的对象是"该 storage 在**时长区间两端**各自的存活区间"⇒ 它需要 `duration.hi`。而 §10.1 行 1405（本轮新加的区分）明写：**「从未建立过标定域片」的算子族走 roofline 初始定价（合法，落 P5 兜底单侧）**⇒ 该 op 的 `duration.hi` **不可计算**。

**构造**：图中存在一个未标定的算子（阶段 3"按族收编"未完成时这是**常态**，而 §13.5 阶段 5 才做后端与报告），且它位于一条 `timing_dependent` 边上（overlap 开启时通信边全部是）⇒ 该边的 `duration.hi` 不可算 ⇒ 受影响 storage 的存活区间上端不可算 ⇒ **`peak_allocated.hi` 不可计算**。

**最坏的一处：这个阻碍在首页看不见。** §10.2b 行 1657 与 §10.5 的强制字段都是 **`S_∞ ∩ live(t*)`**；§10.3 第一段同样是 `S_∞ ∩ live(t*)`。而 `S_∞ := { q : interval(q) 至少一端不可计算 }` **是全体量的集合**，`duration` 确实在里面 —— 但 **`live(t*)` 是 storage 的集合，`duration` 不是 storage** ⇒ `duration ∉ live(t*)` ⇒ **交集把它滤掉** ⇒ 首页清单与判定阻碍分解**都不列它**，而它是使 `peak.hi` 不可算的真正原因。⇒ 用户拿到的工单**漏掉了唯一该做的那件事**（去标定那个算子族）。

**相乘的机制**：`.hi` 换构造（本轮）把**时间侧的不确定性引进了显存侧的 `.hi`**；而 `S_∞ ∩ live(t*)` 这个口径（上一轮定的）是**纯显存的**。两条各自对，合起来漏。

**最小修补**：首页与 §10.3 第一段的口径从 `S_∞ ∩ live(t*)` 改为 **`S_∞ ∩ influences(peak)`**，其中 `influences(peak) := { q : q 出现在 peak_interval 两端任一端的 `expr` 中 }` —— 这是一次对已有 `expr` 字段（`Q[T]` 的规范形，行 232）的**可达性查询**，机器可算、零新构件，且它自动包含 `live(t*)`、自动包含新引进的 duration、自动跟上任何未来的合成式改动。**"清单的口径必须由合成式导出，不能手写一个集合"——这与 `sweep_dims` 从枚举改导出、域片从声明改导出是同一招，正文自己用过两次。**

# 5. 最强与最弱（自评）

**最强：R2 + M2（来源④ 扩到 `replication` 后，对存在性型复刻规则端点倒置 ⇒ `interval.lo > interval.hi`）。**

理由：

3. **它精确复现了台账总结的那个复发模式**：修复（扩域救 alias）把一个未受控的二选一从"兜底"搬到了"来源④"，而来源④ 不落兜底 ⇒ 不进 `S_∞` ⇒ 不进首页清单 ⇒ 不进判定阻碍分解。**新位置比旧位置隐蔽**，这正是历史上七次的共同结构。
4. **它之所以躲过五轮**：`replication` 是**第一个含"该对象存不存在"语义的根**（P4 存在位下传是全篇承重墙），而来源④ 原本的三个根都是"该量取值多大"的断言。扩域是一行文字改动，而它跨越了一条语义边界。**"适用域"这个词把语法谓词和语义前提混成了一件事**——而这正是 L-009 当初引入适用域时想解决的问题的镜像。

**最弱：R13(b)（高维凸包使诚实标定也恒越域）。**

理由：它的核心论断"真实标定点集通常是一条曲线而非网格，因而其凸包在 `D ≥ 5` 维空间里体积为 0"依赖**这三份文件之外的工程经验**（标定实践长什么样）。四份文件里唯一能给我纯文本支点的是 §10.1 的"形状/**类型**插值"（说明域片确实是多维的）与 §13.3 的 `D ≤ 16`——都只能支持"维数不低"，支持不了"点集是曲线"。

R13 的 **(a)（离散维上凸包无定义）是硬的**：`dtype` 进域片有正文依据（§10.1 分级回退第二级、`CalibKey` 的 `measured_quantity` 闭集），而 `conv({fp16, fp8})` 在任何读法下都没有定义，两种补全各有一条硬后果。我把 (b) 写进第 1 节，是因为它与 (a) 指向同一处修补（两段式域片），且它标出了一个正文完全没有讨论过的方向——**凸包这一招是从 `sweep_dims` 的"枚举改导出"类比过来的，而那次类比的对象是一个离散字段集合，这次的对象是一个连续参数空间；两者的"导出"在数学上不是同一件事，而正文行 1891 逐字把它们称为"**是同一招**"。** 这一句可以被辩解为修辞，所以我把 (b) 标为**成立但最弱**，不标"疑点"。

**另标一条疑点，未构造出反例**：`inf_witness` 的 `roots ⊆ {source, configured, transcribed}` **排除 `calib`** —— 我判定它是手滑（R6(c)），但也可能是有意的（"不让标定值成为下界的支撑，避免用链的输入撑起链的结论"）。若是后者，则它与 §2.5 行 481-483 的产品路线论证冲突，需要正文显式说明；我没能从四份文件里判定哪一种，故标**疑点**，修补建议仍为"加 `calib` 或写明为什么不加"。
